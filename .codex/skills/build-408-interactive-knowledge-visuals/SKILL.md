# 408 交互知识可视化

## 目标

把“值得看见的机制”做成可操作的 HTML 知识图，而不是给每段文字加装饰。Markdown 与 LaTeX 始终是可审计的知识源；React 只负责表现和交互，不能成为内容的唯一存放位置。

## 开始前

1. 定位网站项目、知识源目录、导入脚本、知识页渲染组件和现有题目路由。
2. 若项目含 `.openai/hosting.json`，先读取并遵守 `sites:sites-building`；本地改造默认不发布。
3. 同时读取 `repair-408-knowledge-pages` skill 的准确性与验收规则。该 skill 不可用时，至少执行“源码—教材—考纲—真题—二手资料”的证据顺序。
4. 完整读取 [可视化数据契约](references/visual-schema.md)，再编辑实现或清单。
5. 先查看页面和源码，记录真正影响理解的问题；不要仅凭截图猜测 DOM 或公式来源。

## 不可破坏的源码契约

- Markdown 是正文、标题、表格、图片说明和插入位置的唯一事实源。
- LaTeX 源码必须留在 Markdown 中；导入时可以生成 KaTeX HTML，但不得用截图、Unicode 近似字符或计算结果替换源码。
- 每个交互图的公式同时写入清单的 `sourceLatex`。渲染层使用该原文生成公式，并保留可检索的源码属性或字段。
- 知识页只用 `<!-- knowledge-visual:<id> -->` 标记插入位置，不在 Markdown 中嵌入脚本、事件处理器或大段自定义 HTML。
- 每科数据放在自己的 `_visualizations.json`；不得把考点文字硬编码进公共 React 组件。
- 现有内容应合理保留和扩展。只有在新可视化完整覆盖原图信息、语义更准确且经过验收后，才移除旧图引用。

## 判断是否值得可视化

优先处理以下关系：

- 算法逐步执行、指针或索引移动；
- 输入规模与时间/空间增长；
- 地址字段、存储层次、流水线和页表结构；
- 进程、线程、调度、同步和状态转换；
- 分层协议、报文封装、握手、窗口和拥塞变化；
- 多条件对比、年度时序和可反复切换的典型例题。

以下内容通常保持正文：单一定义、短结论、无需切换的两项对照、纯装饰插画、不能提升理解的循环动画。

每个候选图先回答三个问题：用户要操纵什么？变化后观察什么？它解释了哪条考纲关系？答不清就不要加交互。

凡正文用 4 步以上的连续数字、数组、队列、页框、拍次、窗口或输入/工作区/输出来表达状态推进，默认必须做成用户驱动的交互轨迹。原始表格保留为核对底稿，表中每一行都应对应一个交互 step；不得为了缩短清单跳过中间状态。只有纯概念对照、单次公式代入和两三行静态枚举可以不做动画。

## 实现流程

### 1. 建立基线

- 记录页面路由、源文件、现有公式、图片、表格、真题关联和窄屏表现。
- 运行当前构建、测试和知识页审计，区分旧问题与本次回归。
- 用浏览器查看桌面与移动尺寸，确认插入位置及页面节奏。

### 2. 写结构化清单

- 在科目根目录建立 `_visualizations.json`，严格使用参考文档中的 schema。
- ID 采用 `<subject>-<topic>-<purpose>`，全站唯一、只含小写字母、数字和连字符。
- `route` 指向该科源目录内的页面目录；同 ID 标记在该页 Markdown 中恰好出现一次。
- 标题说明“解释什么”，摘要说明“怎么操作、看什么变化”，不写空泛的“交互演示”。
- 公式、数字、状态和步骤必须与原文一致。必要的扩展先依据考纲、教材和真题校对。
- 渐近复杂度图展示的是代表函数的增长示意，不能称为算法的“准确操作次数”；任意视觉长度也不能冒充字节数或真实定量比例。

### 3. 构建公共渲染层

- 导入器读取四科清单，把匹配页面的结构化 spec 和保留的公式源码传给前端。
- 知识页将 HTML 按标记切分，在原语义位置挂载可视化；正文仍按原顺序渲染。
- 使用语义化 HTML、CSS 和 React 状态实现。精确技术图优先 HTML/CSS；无需像素画时不生成位图，也不使用模型手写 SVG。
- 公共组件只实现通用图型：增长曲线、算法跟踪、空间尺度、流程、状态机、时间线、对比、地址字段，以及可编辑的银行家检查、资源分配图和信号量步骤实验。
- 同一页共享字体、色板、圆角和间距。颜色用于区分类别或状态，不作为唯一信息载体。
- 动画只响应用户操作或用于解释状态变化；支持键盘、清晰焦点、动态结果播报和 `prefers-reduced-motion`，不得默认无限循环。
- 窄屏下不横向挤压正文：控件换行、图例可折叠或纵向排列、正文无需频繁横向滚动。

### 4. 连接学习路径

- 可视化附近保留对应知识点标题、相关知识链接和站内批量真题入口。
- 真题入口必须使用现有知识点筛选路由，不建立孤立练习页面。
- 交互图不能遮挡侧栏、题目入口、登录状态或阅读进度。

## 多 subagent 分工

并行前先写清文件所有权，禁止多个 agent 同改公共文件。

- **公共框架负责人**：只改导入器、共享类型/组件、知识页挂载逻辑、公共样式和对应测试；不改四科 Markdown 与清单。
- **科目负责人**：只改被分配科目的 Markdown、资源和该科 `_visualizations.json`；不改共享组件。数据结构与组成原理可为一组，操作系统与网络可为一组。
- **集成负责人**：合并后运行审计，补齐缺失的通用类型，统一视觉节奏并执行浏览器验收。

科目负责人先做高价值页面，避免机械地给所有页面加图。每页通常 0–2 个交互图；同一知识关系只表现一次。

## 验收

每轮必须执行：

```bash
node .codex/skills/build-408-interactive-knowledge-visuals/scripts/audit-visualizations.mjs --project <网站项目绝对路径>
```

随后依次执行：

1. 原知识页/LaTeX/图片审计；
2. 生成知识数据；
3. 类型检查、测试、lint 和生产构建；
4. 浏览器验收代表性页面：首次加载、交互、刷新、直接深链、桌面和窄屏；
5. 检查控制台错误、坏图、公式溢出、标记明文泄漏和布局跳动。

必须达到：

- 清单、页面和标记一一对应；
- 公式源码仍可从 Markdown 与生成数据中取得；
- 无任意 HTML/脚本配置、无外部资源偷渡、无自动循环动画；
- 控件可键盘操作，颜色之外还有文字/形状提示；
- 旧图删除后没有信息损失；
- 相关真题链接命中现有站内批量题目页面；
- 构建、测试、审计和浏览器代表性路径通过。

## 交付

报告新增了哪些通用图型、改造了哪些页面、保留了哪些公式源码、删除或替换了哪些旧资源，并给出审计/测试/构建/浏览器证据。仍未可视化的页面按“没有必要”与“待实现通用图型”分开列出。
