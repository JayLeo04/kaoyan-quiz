# 优化 408 知识页

把原始 Markdown 当作唯一内容源与不可丢失基线；`app/data/knowledge*.json` 与 `public/knowledge/` 都是生成物，绝不直接编辑。

## 0. 不可妥协的三条原则

- 保留原始 Markdown 中的定义、推导、例题、代码、表格、链接、图片语义和考点覆盖；只能增量修复结构、措辞错误或呈现，不能把长文压缩成摘要、以新内容覆盖旧内容，或因美化而删去知识信息。
- 在改动前后审阅源文件差异；除明确的乱码、重复内容或用户认可的错误外，不接受知识性正文的删除。若必须停止渲染旧图，保留其来源或“旧资源 → 新呈现”的可追溯记录，并确认新呈现完整保留原图信息。
- 先让正文无需交互也能讲清结论、概念和步骤，再添加视觉补充。只有图能显著降低理解成本时才添加；一张图或一个交互只服务一个核心结论，不用装饰性、文字堆叠或需要反复猜测含义的可视化。

## 本轮复盘：高频问题与有效解法

- 将“章节顺序混乱”先定位为导入器建模问题：从父级 `index.md` 的直接链接生成顺序，而非按文件名排序；随后只重新导入受影响科目。
- 将“没有表格、只有长文本”“子标题高度不合适”先还原为 Markdown 结构问题：使用真实表格、列表与层级标题，避免用缩进和加粗承担结构语义。
- 将银行家算法、资源分配图、生产者—消费者和哲学家就餐等过程性知识改为可调参数、可逐步推进、可回看代码高亮的交互；让图负责状态变化，正文负责完整解释。
- 将旧 SVG 的“丑”拆成可验证标准：新交互必须覆盖旧图的标签、方向、状态与结论，才移除旧资源；以当前页面 DOM 的实际 `img[src]` 为准，不以 SSR 页面源码中同科数据的残留为准。
- 将“首页卡片显示不全”作为容器高度与溢出问题验收：同时检查 `scrollHeight`、`clientHeight`、桌面和窄屏，而非仅看单一截图。
- 将本地服务需求与页面修复分开处理：用 LaunchAgent 的 `RunAtLoad`、`KeepAlive` 和 `127.0.0.1:3001` 绑定实现开机常驻，不绑定当前对话或外网部署。
- 将“某章少了很多知识点”落实为逐个叶子页的对照清单：不要只比较章首页；按原站的子页路径、标题、表格、公式、例子和图示逐项核验，再把遗漏增量补回本地 Markdown。
- 将原站内链本地化视为内容迁移的一部分：只把能一一映射到本地知识页的 `csgraduates.com` 链接改为本地路由；保留无本地等价物的外部资料链接，并在浏览器实际点击核验深链。
- 将“本地已好、发布后缺内容”定位为构建输入完整性问题：发布前确认 `app/data/knowledge*.json` 与 `public/knowledge/**` 已由定向导入生成、未被忽略，并在公网逐页验证深链、资源与交互，而不是只验证首页构建成功。

## 近期跨科审计的新增准则

- 为每一科先建立**双基线**：`--source-only` 审计确认 Markdown、资源和 marker 本身可解析；再以已确认基线做保真审计。标题数量变化只能是待解释的告警，必须逐页确认它来自思维导图展开、伪标题转正或其他可追溯迁移，不能批量忽略。
- 先修复结构丢失，再润色文字。典型信号是“独立的粗体短语 + 后续段落”承担小节标题、连续字段名和说明伪装成表格、目录页由思维导图变为正文后漏掉分支。分别恢复为真实标题、Markdown 表格和完整的分层/跨章清单；不以缩短正文来换取整洁。
- 目录页迁移时逐项核对原有分支。属于其他章节集中讲解的内容（例如 CPU 与总线/I/O 的衔接）仍要在原位置保留其知识范围和去向，明确标为“跨章衔接”，而不是因重排目录而消失。
- 对技术纠错采用“事实核对 → 最小改写 → 保留上下文”：修正术语归类、公式排版、拼写、示例和易误解表述，但不把定义、推导、例子或原有比较维度删成结论口号。无本地题库统计依据时，不新增或放大“每年必考、固定分值”等频率断言。
- 对过程型机制优先使用一张能改变状态的交互图（如 Cache 的地址字段、组内比较和命中路径）；若关系本身是静态对照，优先使用清晰表格或简洁 SVG。交互必须有可读的默认状态、步骤/回退和正文结论，不能替代正文或制造第二份信息源。
- 批量修复后只定向导入已稳定的科目，并分别审计源稿和生成数据。将“0 错误”和“已逐项说明的既有告警”分开报告；在桌面和约 390 px 窄屏检查实际 DOM 的本地链接、横向溢出、图片替代文本和交互可达性。

## 本轮 DS / CO 保真审校进一步固化的准则

- 先完成“目录页 → 每个叶子页 → 资源与 visual marker”的全量阅读，再动笔处理单页。目录页、思维导图和跨章引导不是可随意压缩的前言：保留分支、学习去向和衔接关系，并把跨章内容明确标为衔接，而非悄然删去。
- 把大幅 Markdown 差异当作风险信号而非成果。优先把伪标题、伪表格、散乱字段和代码前后的断裂恢复为真实结构；重组时保留定义的限定条件、比较维度、推导过程、例子与边界情况，不能只留下一个“结论版”段落。
- 对算法、公式和代码采用“三处一致”核验：正文叙述、符号/公式、示例输出必须互相吻合；可手算或执行的小例子先复算，再写回页面。尤其注意下标起点、循环边界、状态转移、术语映射和缩写展开，不能因排版优化带入新的错误。
- 纠正技术事实时遵循“错误结论改正、解释维度保留”。把过度绝对化的说法改写为教材模型、题设条件或适用范围；保真审计发现原文片段覆盖率下降时，先找回被重组掉的有效信息，再补上正确限定，绝不为通过覆盖率而原样恢复错误结论。
- 将可视化按知识关系选型：静态的组成/对照优先表格或简洁 SVG，动态的匹配、映射、访问、调度或状态转换才做逐步交互。交互数据放在本科 `_visualizations.json`，Markdown 仅在原语义位置放 marker；每一步须能从初始状态、当前动作和结论独立读懂，并可前进/回退。
- 对替换图和新增素材建立可追溯关系：确认新图覆盖旧图的必要标签、方向、数值与结论；SVG 只保留理解所需的短标签，详细解释留在正文。不要把文字密集截图换成另一张文字密集图，也不要让图成为唯一的信息来源。
- 对站内链接按“可精确映射才本地化”处理：真题入口、同科知识页和父子章节要实际打开验证；没有本地等价物的外部参考资料保留外链，不伪造路由。链接改写、标题迁移和 visual 顺序都以源 Markdown 的语义位置为准。
- 维持生成边界与验收顺序：只改 `local/kaoyanzahuopu/**` 源稿及其资源/spec，待 `source-only`、保真与可视化审计通过后才定向导入；生成数据、构建和浏览器验收分别确认。把既有的无关 lint 问题单列报告，不借本次页面修复改动无关组件。

## 本轮批量保真修复补充的判定方法

- 对改动较大的叶子页建立“原片段 → 新位置/纠错说明”的语义映射。`git diff --stat` 的净删除量不是质量指标：只有每个有效定义、条件、推导、例子和结论都能在新结构中找到，或能说明其被何种正确表述替代，才能接受较大的结构性差异。
- 把技术事实核对拆成三个层面：教材模型或 ISA/运行环境的适用范围、公式与符号/单位/边界、可手算或可运行的例子。不得从某一体系结构、运行模式或指令集的特例推广成普遍结论；也不得仅修正结论而丢失它原有的解释链。
- 将三类审计看成互不替代的关卡：`source-only` 检查 Markdown、资源和 marker 是否可解析；保真审计检查基线语义、标题迁移与正文删除；可视化审计检查 marker、spec 与交互契约。任一项未通过，都不能用另一项的“0 问题”抵消。
- 将“源稿稳定”定义为审计通过且高风险差异已逐页解释，而不是页面暂时能显示。随后才定向导入受影响科目；导入后再核对生成数据、构建产物和浏览器深链，避免把生成缓存当成源稿已修复的证据。
- 将验收从“页面能打开”提升为“学习路径可用”：父级目录能到达、子页顺序合理、站内跳转和锚点可刷新直达；正文、表格、公式和交互在桌面与窄屏均完整可读。把无关的既存问题与本次结果明确隔离。

## 本轮优化的闭环

每一次修复都按同一条链路收敛：**原文/原站子页建立基线 → Markdown 做保真增量修复 → 导入器生成数据与资源 → React/CSS 呈现 → 浏览器交互验收 →（需要时）公网深链验收**。任一环节不通过都回到对应层修复，避免在生成物、截图或部署结果上打补丁。

## 1. 定位与建立基线

1. 对用户给出的 URL 运行：

   ```bash
   node .codex/skills/review-408-page-by-url/scripts/resolve-page.mjs --json '<URL>'
   ```

2. 在浏览器查看目标页的顶部、中段、底部和窄屏；完整阅读对应 `index.md`、同目录 `assets/`、父级 `index.md` 与该科 `_visualizations.json`。
3. 先区分问题属于原文语义、导入器顺序、共享渲染组件、CSS，还是未重新导入的旧生成数据；不要凭截图猜测源文件。
4. 同时遵守 `preserve-408-markdown`、`repair-408-knowledge-pages`；需要交互时遵守 `build-408-interactive-knowledge-visuals`。

## 2. 按学习路径组织章节

- 子章节顺序以父级 `index.md` 中的直接链接为准，不按文件名字典序或目录深度猜测。
- 在导入器中从父页直接链接推导顺序；同一页多个交互 spec 必须按 Markdown marker 的出现顺序输出。
- 修改导入器后，对受影响科目定向重新导入：

  ```bash
  npm run knowledge:408 -- --subject ds|co|os|cn
  ```

- 若测试发现源清单存在、生成数据却缺失，先定向导入对应科目；不要只放宽测试。不要为了刷新顺序而导入一个尚未通过本身公式/可视化审计的无关科目。

## 3. 恢复正文层次与页面节奏

- 对比项使用真正的 Markdown 表格；枚举使用列表；不要以连续缩进段落伪造表格或项目符号。
- 用准确的 `##`、`###`、`####` 表达定义、机制、算法步骤和例外，避免把“银行家算法”“绝对装入”等应有小节写成普通加粗段落。
- 采用“先结论/定义、后机制/步骤、再例子或边界”的阅读节奏；给术语必要的短解释，但不以口号或泛泛比喻替代严谨表述。
- 保留原有定义、推导、例题和有效图片；只作增量修复，不把长文压缩成摘要。正文中相同信息可通过标题、表格、列表重组得更易读，但不得减少其可获得的信息。
- 调整公共标题间距或图文布局时，检查桌面和窄屏，避免新增全局溢出或裁切。

## 4. 用简洁交互补充理解，同时保留信息

- 默认保留原图与正文说明。低质量、文字堆叠的旧图只有在新交互覆盖其关键标签、方向、状态和结论后，才可停止在当前页渲染；记录“旧资源 → 新 visual ID”，不让知识信息随资源替换消失。
- 在 Markdown 的原语义位置保留唯一标记：

  ```md
  <!-- knowledge-visual:os-example-purpose -->
  ```

- 在本科 `_visualizations.json` 保存所有步骤、公式、数值和说明；公共 React 组件只实现通用图型。让每个视觉有明确标题、一个主结论、少量必要标签和紧邻的文字说明。
- 为过程性内容选择适合的图型：

  | 知识关系 | 必备交互 |
  | --- | --- |
  | 银行家算法 | 可编辑 Available / Max / Allocation；Need 自动计算；逐步展示 Work、回收和安全序列。 |
  | 资源分配图 | 至少提供单实例与多实例两例；显示请求/分配箭头及“有环”判定边界。 |
  | 信号量同步 | 逐步展示缓冲区或资源归属、信号量状态、当前行为和高亮代码行。 |

- `sourceLatex` 必须与 Markdown 中完整定界的 LaTeX 一致；不把公式、代码或正文硬编码进共享组件。
- 折叠代码使用原生 `<details>`，默认收起。图中只保留理解图形所必需的简短标签，详细说明放在可访问的正文或交互状态中；若表格或列表已能更清楚说明关系，就不要额外造图。

## 5. 处理“页面仍命中旧资源”的假象

- 先在当前页面 DOM 查询具体的 `img[src]`，再判断旧资源是否仍被显示。
- SSR HTML 可能序列化同科其他页面的数据；原始 HTML 中出现同名 `inline-svg-06.svg` 不等于目标页仍在使用该图。
- 在原文、生成页数据和实际 DOM 均不引用后，才删除孤立旧资源；重新导入对应科目以清除 public 副本。

## 6. 对照来源、站内链接与发布

- 当用户要求“与原文对比”时，从指定章节的每一个子页开始，而不是只读父级目录；建立“原路径 → 本地路径 → 已覆盖/待补充”的清单，并逐项检查标题层次、定义、推导、表格、例题、代码、图示与考纲点。
- 优先将原站同一知识库中的链接改为本地 `/knowledge/...` 路由。通过路由映射解析旧 URL，不能确定映射时不要猜测或制造失效链接；外部代码仓库、论文等没有本地副本的资料仍保留外链。
- 链接改写后在实际浏览器点击或访问目标地址，检查直接打开、刷新深链、上一篇/下一篇和窄屏导航；不要只用文本搜索证明链接可用。
- 用户要求发布时，使用项目的 Sites 工作流。发布前重新生成受影响科目的 `app/data/knowledge*.json` 和 `public/knowledge/**`，确认这些构建输入没有被 `.gitignore` 排除；发布后从公网 URL 直接打开至少一个章节页和一个深层知识页，验证正文、图片/SVG、交互和本地化链接。
- 保持本地常驻服务与公网发布相互独立：前者按 LaunchAgent 管理，后者按托管平台管理；不要让任一项依赖当前对话或终端会话。

- 父级目录、侧栏和上一篇/下一篇顺序；
