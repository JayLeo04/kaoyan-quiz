# 第 10 章 内部排序

> **📌 本章主线**
>
> 排序把记录序列按关键字重排为有序序列。复习时先抓住“比较关键字、移动记录”两种基本操作，再分别掌握插入、交换、选择、归并和基数排序的推进方式、不变量、复杂度成立条件与稳定性。

> **🎯 408 复习定位**
>
> 需要能手推一趟排序、判断中间序列，能说明算法在何种初态下达到最好或最坏情况，能写出直接插入、快速划分、堆调整、二路归并等核心过程，并能区分稳定性、辅助空间和比较排序下界。

## 10.1 排序的对象、评价维度与存储

<!-- source: section="10.1" source_file="10-1-overview/index.md"
     pdf_pages="273-274" book_pages="263-264" items="式(10-1)～式(10-3), 顺序表类型" -->

### 排序、关键字与稳定性

设待排序记录序列为

$$
\{R_1,R_2,\ldots,R_n\},\tag{10-1}
$$

相应关键字为 $K_1,K_2,\ldots,K_n$。排序就是确定原下标的一种排列 $p_1,p_2,\ldots,p_n$，使

$$
K_{p_1}\le K_{p_2}\le\cdots\le K_{p_n},\tag{10-2}
$$

并把记录重排为

$$
\{R_{p_1},R_{p_2},\ldots,R_{p_n}\}.\tag{10-3}
$$

将式（10-2）的 $\le$ 改为 $\ge$，就得到按关键字非递增排序。关键字可以是主关键字、次关键字或若干数据项的组合；主关键字唯一时排序结果唯一，次关键字可能重复时结果不唯一。

若 $K_i=K_j$ 且排序前 $R_i$ 在 $R_j$ 之前，排序后仍保持这一先后关系，则该排序方法对这两个记录是稳定的；方法能对所有输入保持等关键字记录的相对次序，才称为稳定排序。证明一个方法不稳定，只需给出一个反例。

> **⚠ 易错提醒**
>
> 稳定性讨论的是“关键字相等但记录不一定相同”的相对次序。只写一串互不相同的数字，无法判断排序方法是否稳定。

### 内部排序与外部排序

- **内部排序**：全部待排记录能同时放入随机存储器，排序过程在内存中完成。
- **外部排序**：记录数量大到内存不能一次容纳，排序过程还要访问外存。

本章只讨论内部排序。按基本原则可分为插入、交换、选择、归并和计数/基数等类；按教材给出的典型工作量，可概括为简单方法 $O(n^2)$、先进方法 $O(n\log n)$ 和基数方法 $O(dn)$。后一写法隐含基数规模相对固定；链式基数排序的完整表达见 10.6 节的 $O(d(n+rd))$。

### 两类基本操作与三种存储方式

大多数内部排序反复执行两种操作：比较两个关键字，必要时改变记录之间的次序。记录很大时，减少整条记录的移动可能比减少比较更重要。

| 存储方式 | 次序由什么表示 | 排序时改变什么 | 排序后特征 |
| --- | --- | --- | --- |
| 连续存储 | 记录的物理位置 | 移动或交换记录 | 可随机访问，适合折半查找 |
| 静态链表 | `next` 指针 | 修改指针，不移动记录本体 | 得到有序链，随机访问能力消失 |
| 记录本体连续存储 + 地址向量 | 地址向量中的下标/地址 | 移动地址项 | 可先得到逻辑有序次序，再按环重排记录 |

第二种实现称为表排序，第三种称为地址排序。静态链表适合排序，是因为排序只改变次序、不增删记录；若最终仍需连续有序存储，还要再做一次记录重排。

### 本章顺序表约定

教材后续算法通常按 1 起始下标访问 `r[1..length]`，`r[0]` 闲置、暂存记录或充当哨兵：

```c
typedef int KeyType;
typedef struct {
    KeyType key;
    InfoType otherinfo;       // 教材约定的其他数据项类型
} RedType;

typedef struct {
    RedType r[MAXSIZE + 1];   // 有效记录在 r[1..length]
    int length;
} SqList;
```

`LT(a,b)`、`LQ(a,b)` 分别表示“小于”和“小于等于”；教材代码中的引用参数、区间赋值和 `<-->` 交换记号属于算法记法，不应直接当作可编译 C。

## 10.2 插入类排序

<!-- source: section="10.2" source_file="10-2-insertion-sorting/index.md"
     pdf_pages="275-282" book_pages="265-272" items="式(10-4)～式(10-7), 算法10.1～10.5, 图10.1～图10.5" -->

插入排序的共同不变量是：处理第 $i$ 个记录前，已经得到一个按关键字有序的子序列；本趟为待插记录寻找位置并维持有序性。各变体主要是在减少比较、减少记录移动或让记录更快跨越长距离之间取舍。

### 直接插入排序（算法 10.1）

第 $i$ 趟把 `r[i]` 插入已经有序的 `r[1..i-1]`，完成后 `r[1..i]` 有序。自右向左查找时同时把所有关键字严格大于待插关键字的记录右移一格：

```pseudo
for i = 2 .. n:
    if r[i].key < r[i-1].key:
        r[0] = r[i]                       // 哨兵兼暂存单元
        r[i] = r[i-1]                     // 已知相邻前项更大，先直接后移
        j = i - 2
        while r[0].key < r[j].key:
            r[j+1] = r[j]
            j = j - 1
        r[j+1] = r[0]
```

`r[0]` 与待插记录关键字相同，因此向左扫描到下标 0 时条件必为假，不需要在循环中另写越界判断。只移动“严格大于”待插关键字的记录，等关键字记录不会越过彼此，所以算法稳定。

最小例：有序前缀 `38,49,65,97` 插入 76 时，从 97 向左找到 $65<76<97$，只把 97 右移，得到 `38,49,65,76,97`。

| 初态 | 关键字比较次数 | 记录移动次数 | 结论 |
| --- | ---: | ---: | --- |
| 正序 | $n-1$ | $0$ | 时间为 $O(n)$ |
| 严格逆序（关键字严格递减） | $\dfrac{(n+2)(n-1)}2$ | $\dfrac{(n+4)(n-1)}2$ | 达到最坏情况 |
| 各种排列等概率 | 约 $n^2/4$ | 约 $n^2/4$ | 平均时间为 $O(n^2)$ |

表内“比较”只统计关键字大小比较，“移动”统计整条记录赋值。严格逆序时，第 $i$ 趟先由外层 `if` 比较 1 次，再从 `j=i-2` 比较到哨兵，共比较 $i-1$ 次，合计 $i$ 次；记录赋值依次为暂存、预移 `r[i-1]`、继续后移和最终插入，共 $i+1$ 次。因此总数分别是 $\sum_{i=2}^n i$ 与 $\sum_{i=2}^n(i+1)$。原输入 Markdown 漏写的 `r[i]=r[i-1]` 和 `j=i-2` 必须成对恢复，否则代码与精确计数不一致。随机排列一行是教材在“各种排列等概率”假设下取最好、最坏计数平均所得的近似值，并非严格期望值推导。辅助空间仅一个记录，为 $O(1)$；$n\le1$ 时外层循环不执行。

### 折半插入排序（算法 10.2）

折半插入把“在有序前缀中找插入点”改为折半查找：令 `low=1, high=i-1`；若待插关键字小于中点关键字就收缩高半区，否则收缩低半区。循环结束时 `low=high+1`，将 `r[high+1..i-1]` 右移，再把待插记录放入 `r[high+1]`。

相等时进入右半区，使新记录插在已有等关键字记录之后，因而保持稳定。它把全程关键字比较数降到 $O(n\log n)$ 量级，但记录移动次数与直接插入相同，所以最坏/平均总时间仍为 $O(n^2)$，辅助空间仍为 $O(1)$。

> **⚠ 易错提醒**
>
> 折半查找只减少“找位置”的比较，不能消除为插入而进行的连续移动，因此不能据此把折半插入排序的总体最坏复杂度写成 $O(n\log n)$。

### 2-路插入排序

2-路插入另设长度为 $n$ 的循环向量 `d`。先把 `r[1]` 放入 `d[1]`，用 `first`、`final` 指向当前有序序列的首、尾；后续记录先与 `d[1]` 比较，再插入它前方或后方的有序区域。循环存储让记录可以向两端选择较短方向移动。

- 代价：需要 $n$ 个记录的辅助空间，即 $O(n)$。
- 教材给出的移动次数约为 $n^2/8$，比直接插入少，但并未消除移动。
- 若首记录恰为全序列最小值或最大值，后续插入集中在一侧，优势完全消失。

### 表插入排序与记录重排（算法 10.3）

表插入排序把记录放在静态链表结点中：

```c
typedef struct {
    RedType rc;
    int next;
} SLNode;

typedef struct {
    SLNode r[SIZE];   // r[0] 是表头结点
    int length;
} SLinkListType;
```

令头结点关键字为 `MAXINT`，先把结点 1 与头结点连成循环链表，再把结点 2 至 $n$ 依次按非递减次序插入。它用约 $2n$ 次指针修改代替记录移动，但寻找插入点所需的关键字比较与直接插入同量级，故排序仍为 $O(n^2)$。

排序结果只是有序链表，只能沿 `next` 顺序访问。若要恢复数组按关键字有序，算法 10.3 `Arrange` 逐个把第 $i$ 小记录换到数组位置 $i$：

```pseudo
p = r[0].next
for i = 1 .. length-1:
    while p < i: p = r[p].next       // 跳过已到位的数组位置
    q = r[p].next                    // 交换前保存后继
    if p != i:
        swap(r[p], r[i])
        r[i].next = p                // 保持仍能找到被移走的记录
    p = q
```

循环开始时 `r[1..i-1]` 已经到位；`p` 指向链中第 $i$ 个记录当前所在位置。最坏时每个未到位记录需要一次交换，即 3 次记录移动，故至多移动 $3(n-1)$ 次，不改变表插入排序的 $O(n^2)$ 总量级。

### 希尔排序（算法 10.4、10.5）

若满足

$$
L.r[i].key<\max_{1\le j<i}\{L.r[j].key\}\tag{10-7}
$$

的记录很少，序列可视为“基本有序”，直接插入会接近线性。希尔排序先按较大增量 $dk$ 把相隔 $dk$ 的记录组成子序列，分别直接插入；不断缩小增量，最后用 $dk=1$ 对全体记录做直接插入。子序列不是连续分段，较小关键字可跨越多个位置向前移动。

```pseudo
ShellInsert(r, n, dk):
    for i = dk + 1 .. n:
        if r[i].key < r[i-dk].key:
            r[0] = r[i]                    // 仅暂存，不是哨兵
            j = i - dk
            while j > 0 and r[0].key < r[j].key:
                r[j+dk] = r[j]
                j = j - dk
            r[j+dk] = r[0]

ShellSort(r, n, dlta[0..t-1]):
    for each dk in dlta:
        ShellInsert(r, n, dk)
```

正确性依赖最后一个增量等于 1；教材还要求整个增量序列的公因子只有 1。希尔排序的时间取决于增量序列，不能脱离增量给出唯一精确复杂度。教材列出的局部结论是：当

$$
dlta[k]=2^{t-k+1}-1,\qquad 1\le k\le t\le\lfloor\log_2(n+1)\rfloor,
$$

时间复杂度为 $O(n^{3/2})$；教材另转述实验性结果：特定 $n$ 范围内比较和移动次数约为 $n^{1.3}$，当 $n\to\infty$ 时可达 $n(\log_2n)^2$ 量级。希尔排序只需一个记录的辅助空间，但会让相同关键字跨组移动，属于不稳定排序。

例如增量依次为 5、3、1 时，第一趟分别处理下标同余于 1～5 的五组记录，第二趟处理三个跨距为 3 的子序列，最后一趟才对整个序列做直接插入。

原书页脚还列出两组增量。应同时服从“增量为正整数、末增量为 1”的算法条件：

- 对序列 $\ldots,9,5,3,2,1$，公式 $dlta[k]=2^{t-k}+1$（$0\le k\le t\le\lfloor\log_2(n-1)\rfloor$）只生成到 2，末尾的 1 需显式追加。
- 对序列 $\ldots,40,13,4,1$，公式 $dlta[k]=(3^{t-k}-1)/2$ 的正增量项应取 $0\le k\le t-1$，并满足 $t\le\lfloor\log_3(2n+1)\rfloor$；原书印成 $k\le t$ 时会多出不可用的 0。

相比之下，正文序列 $2^{t-k+1}-1$ 在 $k=t$ 时自动得到末项 1，不需要另补。

### 起泡排序

第 $i$ 趟从 `r[1]` 扫到 `r[n-i+1]`，比较相邻记录，遇到逆序就交换。本趟结束后，未排序区的最大关键字到达末端位置 `r[n-i+1]`，并从下一趟中排除。

若一趟中没有发生交换，整个序列已经有序，可以提前结束。正序只比较 $n-1$ 次，时间为 $O(n)$；关键字严格递减时需 $n-1$ 趟，共比较

$$
\sum_{i=2}^{n}(i-1)=\frac{n(n-1)}2,
$$

并作同数量级移动，最坏时间为 $O(n^2)$。只在严格逆序时交换，相同关键字记录不互换，因此该实现稳定，辅助空间为 $O(1)$。

### 快速排序的划分不变量

快速排序先选一个枢轴，把 `r[low..high]` 划分为两部分：枢轴最终位置左侧关键字均不大于它，右侧均不小于它，再递归排序两侧。算法 10.6(a) 让枢轴在两端找到越界记录后与之交换，每次交换需 3 次记录赋值；算法 10.6(b) 先把枢轴暂存在 `r[0]`，只让找到的记录单向填入当前空位，最后再放回枢轴，避免排序途中反复赋值枢轴：

```pseudo
Partition(r, low, high):
    r[0] = r[low]
    pivotkey = r[low].key
    while low < high:
        while low < high and r[high].key >= pivotkey: high--
        r[low] = r[high]              // 小关键字填入低端空位
        while low < high and r[low].key <= pivotkey: low++
        r[high] = r[low]              // 大关键字填入高端空位
    r[low] = r[0]
    return low
```

循环过程中始终只有一个待填位置：从右侧找到小于枢轴者填低端后，空位转到高端；从左侧找到大于枢轴者填高端后，空位又转回低端。`low==high` 时把枢轴填入，划分完成。两端扫描都保留 `low<high`，且对等关键字分别使用 `>=`、`<=`，才能保证指针推进并防止越界。

以 `49 38 65 97 76 13 27` 和枢轴 49 为例，图 10.7(a) 对应算法 10.6(b) 的“枢轴另存、空位交替移动”过程；`□` 表示当前待填位置：

| 状态 | 关键字序列 |
| --- | --- |
| 初始 | `49 38 65 97 76 13 27` |
| 从右端移入 27 后 | `27 38 65 97 76 13 □` |
| 从左端移入 65 后 | `27 38 □ 97 76 13 65` |
| 从右端移入 13 后 | `27 38 13 97 76 □ 65` |
| 从左端移入 97 后 | `27 38 13 □ 76 97 65` |
| 枢轴 49 填入空位 | `27 38 13 49 76 97 65` |

所以一次划分得到 `27 38 13 | 49 | 76 97 65`；两侧各自仍未必有序，只满足相对于枢轴的大小分区条件。

### 快速排序递归、复杂度与改进

```pseudo
QSort(r, low, high):
    if low < high:
        pivotloc = Partition(r, low, high)
        QSort(r, low, pivotloc - 1)
        QSort(r, pivotloc + 1, high)
```

算法 10.8 的入口只是调用 `QSort(r,1,n)`。

设一次划分耗时 $cn$。若输入是随机排列，枢轴最终落在 $1..n$ 各位置的概率相同，则平均时间满足

$$
T_{avg}(n)=cn+\frac2n\sum_{i=0}^{n-1}T_{avg}(i).\tag{10-8}
$$

由此可推出教材给出的上界

$$
T_{avg}(n)<\left(\frac b2+2c\right)(n+1)\ln(n+1),\qquad n\ge2,\tag{10-9}
$$

所以平均时间为 $\Theta(n\log n)$。若每次划分都极不均衡，例如首元素作枢轴而输入已按关键字有序或基本有序，递推退化为 $T(n)=T(n-1)+\Theta(n)$，最坏时间为 $\Theta(n^2)$。快速排序存在跨越式移动，是不稳定排序。

教材强调快速排序在同为 $O(n\log n)$ 的方法中平均常数因子较小；这一评价依赖划分较为均衡，不能替代最坏情况分析。

- 划分较均匀时，普通双递归实现的递归栈最大深度为 $\lfloor\log_2n\rfloor+1$，辅助空间为 $O(\log n)$。
- 枢轴总偏向一端时，普通双递归实现的栈深可达 $n$，辅助空间为 $O(n)$；只交换两个递归调用的先后顺序不能改变这一最坏界。
- “三者取中”比较首、尾和中点关键字，以中值作枢轴，能改善有序/近有序输入上的表现，但不消除理论最坏情况。
- 教材还提出在两端扫描时同时做相邻起泡并记录两侧是否发生交换；某侧无交换时可跳过该子表。它属于改进思路，不改变划分正确性的核心条件。

若要在任意划分下把递归栈保证为 $O(\log n)$，实现必须只递归处理较短子区间，并在当前栈帧中循环处理较长子区间：

```pseudo
QSortBounded(r, low, high):
    while low < high:
        p = Partition(r, low, high)
        if p - low < high - p:
            QSortBounded(r, low, p - 1)    // 递归较短左侧
            low = p + 1                    // 循环处理较长右侧
        else:
            QSortBounded(r, p + 1, high)   // 递归较短右侧
            high = p - 1                   // 循环处理较长左侧
```

每次真正压栈的子区间长度至多是当前区间的一半，故递归深度为 $O(\log n)$；较长一侧不新增栈帧。

选择排序每趟从未排序区选出最小或最大记录，把它放到最终位置。改进方向不是减少记录移动，而是复用已经得到的比较信息。

### 简单选择排序（算法 10.9）

第 $i$ 趟在 `r[i..n]` 中找最小记录，与 `r[i]` 交换；完成后 `r[1..i]` 已是全序列前 $i$ 小记录且位置固定。

```pseudo
for i = 1 .. n-1:
    j = index_of_min_key(r[i..n])
    if i != j: swap(r[i], r[j])
```

无论初态如何，比较次数恒为

$$
\sum_{i=1}^{n-1}(n-i)=\frac{n(n-1)}2,
$$

故时间为 $O(n^2)$。交换次数在 0 到 $n-1$ 之间；按一次交换 3 次赋值计，记录移动最多 $3(n-1)$ 次。辅助空间为 $O(1)$。

简单选择排序不稳定。例如记录序列 `2a, 2b, 1` 首趟把 `1` 与 `2a` 交换，得到 `1, 2b, 2a`，两个关键字同为 2 的记录次序被逆转。

稳定性由具体移动规则决定，不能由时间复杂度推出。原书 10.7 节“所有 $O(n^2)$ 的简单排序法都是稳定的”这一概括不适用于算法 10.9：直接插入、按相等关键字不交换的起泡可以稳定，而上述标准交换式简单选择排序不稳定。

### 树形选择排序

树形选择排序又称锦标赛排序。$n$ 个叶子依次保存待排关键字，每个内部结点保存左右孩子中的较小值，根就是当前最小值。输出最小记录后，把对应叶子改为“最大值”，只沿该叶到根的路径重新比较，根就变为下一小值。

精确计数采用“补齐选择树”模型：令

$$
m=2^{\lceil\log_2n\rceil},
$$

把不足的 $m-n$ 个叶子填为“最大值”哨兵。此时树按结点层数计的深度为 $\lceil\log_2n\rceil+1$，每次从叶到根更新恰经过 $\lceil\log_2n\rceil$ 个比较层；当 $n$ 是 2 的幂时，它与原书的 $\lfloor\log_2n\rfloor+1$ 一致。首次建树用 $O(m)=O(n)$ 次比较，随后输出其余记录各需 $O(\log n)$ 次，故总时间为 $O(n\log n)$，整棵树的辅助存储为 $O(n)$。代价还包括与“最大值”哨兵的多余比较。

### 堆、筛选与建堆

$n$ 个元素的 1 起始序列 $\{k_1,k_2,\ldots,k_n\}$ 满足下列任一组关系时称为堆；只对不超过 $n$ 的孩子下标使用相应不等式：

$$
\left\{\begin{aligned}
k_i&\le k_{2i},\\
k_i&\le k_{2i+1}
\end{aligned}\right.
\quad\text{或}\quad
\left\{\begin{aligned}
k_i&\ge k_{2i},\\
k_i&\ge k_{2i+1}
\end{aligned}\right.,
\qquad 1\le i\le\left\lfloor\frac n2\right\rfloor.
$$

把数组看成完全二叉树，前者是小顶堆，堆顶为最小值；后者是大顶堆，堆顶为最大值。最后一个非叶结点下标为 $\lfloor n/2\rfloor$，因此从这里向前逐个“筛选”即可自底向上建堆。

教材例中 `96,83,27,38,11,09` 是大顶堆，`12,36,24,85,47,30,53,91` 是小顶堆；判断时应按数组下标对应的父子关系逐边检查，而不是只看整体最大值或最小值是否位于首项。

`HeapAdjust(H,s,m)` 的前置条件是：`H[s..m]` 除根 `H[s]` 外，根的左右子树都已是大顶堆。先暂存根记录 `rc`，每次选择关键字较大的孩子上移，直到 `rc` 不小于该孩子或到达叶子，再把 `rc` 放入空位：

```pseudo
HeapAdjust(H, s, m):
    rc = H[s]
    j = 2*s
    while j <= m:
        if j < m and H[j].key < H[j+1].key: j++
        if rc.key >= H[j].key: break
        H[s] = H[j]
        s = j
        j = 2*s
    H[s] = rc
```

### 堆排序（算法 10.10、10.11）

为得到非递减序列，先建大顶堆；随后反复把堆顶最大记录与当前堆尾交换，缩小堆区并从根重新筛选：

```pseudo
for i = floor(n/2) downto 1:
    HeapAdjust(H, i, n)

for i = n downto 2:
    swap(H[1], H[i])
    HeapAdjust(H, 1, i-1)
```

第二个循环开始时，`H[1..i]` 是待排序区且 `H[i+1..n]` 已按非递减次序到位；交换把待排序区最大值放到位置 $i$，筛选恢复前缀的堆性质。

深度为 $k$ 的堆，一次筛选至多比较 $2(k-1)$ 次。教材按各层子树深度求和，给出建初始堆的关键字比较总数不超过 $4n$；之后 $n-1$ 次调整的比较总数小于

$$
2n\lfloor\log_2n\rfloor.
$$

因此堆排序最坏时间为 $O(n\log n)$，仅需一个记录的交换空间，即 $O(1)$。根与堆尾的远距离交换可能改变等关键字记录的相对次序，所以堆排序不稳定。

教材指出：记录数很少时，建堆和反复筛选的固定工作使堆排序不占优势；$n$ 较大且需要最坏 $O(n\log n)$ 保证、又不能提供 $O(n)$ 辅助记录空间时，它更有价值。

## 10.5 2-路归并排序

<!-- source: section="10.5" source_file="10-5-merge-sort/index.md"
     pdf_pages="293-294" book_pages="283-284" items="算法10.12～10.14, 图10.13" -->

归并是把两个或多个有序表组合为一个新的有序表。两个长度分别为 $m$、$n$ 的有序表，无论用顺序存储还是链式存储，都可在 $O(m+n)$ 时间内归并。

2-路归并排序把初始序列看作 $n$ 个长度为 1 的有序段；每趟把相邻两段两两归并，段长依次变为 $2,4,8,\ldots$，直至只剩一个长度为 $n$ 的有序段。总趟数为 $\lceil\log_2n\rceil$。

### 归并操作（算法 10.12）

```pseudo
Merge(SR, TR, i, m, n):
    j = m + 1
    k = i
    while i <= m and j <= n:
        if SR[i].key <= SR[j].key:
            TR[k++] = SR[i++]
        else:
            TR[k++] = SR[j++]
    copy SR[i..m] or SR[j..n] 的剩余部分到 TR
```

循环前，`TR` 已写入部分是两个输入段中已处理记录的有序归并；每次取两段当前首记录中较小者即可保持不变量。关键字相等时先取左段记录，因而保持原相对次序，归并排序稳定。

### 递归归并排序（算法 10.13、10.14）

递归形式把 `SR[s..t]` 平分为 `SR[s..m]` 与 `SR[m+1..t]`，分别排序到临时数组，再调用 `Merge`。基本情况是 `s==t`，直接复制单个记录。每层归并处理 $n$ 个记录，共 $\lceil\log_2n\rceil$ 层，所以时间为 $O(n\log n)$；需要与待排记录等量的辅助数组，空间为 $O(n)$。

教材把算法 10.13、10.14 写成带区间赋值和交替临时数组的算法记法，并评价其递归形式实用性较差；阅读时应抓住“分治到单元素—逐层归并”的机制，不把该段直接当作可编译 C。

## 10.6 多关键字与链式基数排序

<!-- source: section="10.6" source_file="10-6-radix-sort/index.md"
     pdf_pages="294-298" book_pages="284-288" items="式(10-10), 算法10.15～10.17, 图10.14" -->

基数排序不比较记录之间的完整关键字，而是把一个逻辑关键字拆为多个有限取值的关键字位，按位反复“分配—收集”。

### 多关键字的字典序

设记录 $R_i$ 含 $d$ 个关键字 $(K_i^0,K_i^1,\ldots,K_i^{d-1})$，其中 $K^0$ 最主、$K^{d-1}$ 最次。对 $i<j$，若存在位置 $l$，满足

$$
K_i^s=K_j^s\quad(0\le s<l),
\qquad K_i^l<K_j^l,
$$

则记作

$$
(K_i^0,K_i^1,\ldots,K_i^{d-1})
<(K_j^0,K_j^1,\ldots,K_j^{d-1}).
$$

这就是按“先比较最主位，只有相等时才比较下一位”的字典序。

### MSD 与 LSD

| 方法 | 处理次序 | 每一层/趟的对象 | 正确性条件 |
| --- | --- | --- | --- |
| MSD（最高位优先） | $K^0\to K^1\to\cdots\to K^{d-1}$ | 先按高位把序列分成子序列，再在各子序列内处理下一位 | 每层保持高位相同的记录成组 |
| LSD（最低位优先） | $K^{d-1}\to K^{d-2}\to\cdots\to K^0$ | 每一趟都处理整个序列 | 除最后一趟外，每一位排序必须稳定，不能破坏已建立的低位次序 |

数值 $0\le K\le999$ 可拆为百、十、个位，固定长度单词可拆为各字符。若每一位都落在相同的 `RADIX` 个值中，就可用队列分配和收集代替关键字比较。

### 链式基数排序（算法 10.15—10.17）

这里必须区分两套下标约定：数学元组仍以 $K^0$ 表示最高位、$K^{d-1}$ 表示最低位；原书算法 10.17 却从 `i=0` 开始做 LSD。要使代码与算法方向一致，数组字段必须采用反向映射

$$
\texttt{keys[pos]}=K^{d-1-pos},qquad 0\le pos<d,
$$

即 `keys[0]` 存最低位，`keys[keynum-1]` 存最高位。若把 `keys[0]` 仍解释为数学记号 $K^0$，循环将变成 MSD 顺序，却又没有对子序列递归，算法不正确。

```c
typedef struct {
    KeysType keys[MAX_NUM_OF_KEY];  // 本算法约定 keys[0] 为最低位
    InfoType otheritems;
    int next;
} SLCell;

typedef struct {
    SLCell r[MAX_SPACE];            // r[0] 是头结点，记录在 r[1..recnum]
    int keynum;
    int recnum;
} SLList;
```

用静态链表存放 $n$ 个记录，并为每个桶维护头指针 `f[0..rd-1]` 和尾指针 `e[0..rd-1]`。每趟处理一个关键字位：

1. **分配**：按当前链表次序扫描记录，根据该位的序号 `ord(key)` 把结点追加到对应队尾；追加而不是插到队头，才能保持桶内原次序。
2. **收集**：按桶号从小到大连接所有非空桶，首个非空桶的头成为新表头，最后一个非空桶的尾指向 0。
3. 从最低位重复到最高位，共进行 $d$ 趟。第 $p$ 趟后，序列按已经处理的 $p$ 个低位关键字有序；稳定分配保证前面各趟的次序不被破坏。

把原书旧式算法记法规范为数组参数、统一的 `RADIX` 常量和显式边界后，核心代码为：

```pseudo
Distribute(r[], pos, f[], e[]):
    for b = 0 .. RADIX-1:
        f[b] = e[b] = 0
    for p = r[0].next; p != 0; p = r[p].next:
        b = ord(r[p].keys[pos])
        if f[b] == 0: f[b] = p
        else:         r[e[b]].next = p
        e[b] = p                         // FIFO 追加到桶尾

Collect(r[], f[], e[]):
    head = tail = 0
    for b = 0 .. RADIX-1:
        if f[b] != 0:
            if head == 0: head = f[b]
            else:         r[tail].next = f[b]
            tail = e[b]
    r[0].next = head
    if tail != 0: r[tail].next = 0

RadixSort(L):
    if L.recnum == 0: return
    for p = 0 .. L.recnum-1: L.r[p].next = p + 1
    L.r[L.recnum].next = 0
    for pos = 0 .. L.keynum-1:          // keys[0]（最低位）到最高位
        Distribute(L.r, pos, f, e)
        Collect(L.r, f, e)
```

以 `278,109,063,930,589,184,505,269,008,083` 为例，三趟收集结果为：

| 趟 | 当前位 | 收集后的链表次序 |
| --- | --- | --- |
| 1 | 个位 | `930,063,083,184,505,278,008,109,589,269` |
| 2 | 十位 | `505,008,109,930,063,269,278,083,184,589` |
| 3 | 百位 | `008,063,083,109,184,269,278,505,589,930` |

每趟分配扫描 $n$ 个结点，为 $O(n)$；收集扫描 $rd$ 个桶，为 $O(rd)$。总时间为

$$
O\bigl(d(n+rd)\bigr).
$$

辅助工作区是 $2rd$ 个队列指针；与顺序存储方法相比，静态链表本身还为 $n$ 个记录增加 `next` 字段。按队尾追加的链式实现稳定。上表逐趟收集序列等价表达了图 10.14 的必要信息。

### 方法对照

| 方法 | 时间特征 | 辅助空间/额外表示 | 稳定性与适用条件 |
| --- | --- | --- | --- |
| 直接插入 | 正序 $O(n)$；平均、最坏 $O(n^2)$ | $O(1)$ | 稳定；适合记录少或基本有序 |
| 折半插入 | 比较降为 $O(n\log n)$，移动仍使平均/最坏为 $O(n^2)$ | $O(1)$ | 按算法 10.2 的“相等向右”规则稳定 |
| 2-路插入 | 仍为 $O(n^2)$，教材给出移动约 $n^2/8$ | $O(n)$ 个记录 | 首记录为极值时失去优势；源文未唯一规定等关键字插入位置 |
| 表插入 | 排序 $O(n^2)$；重排另需 $O(n)$ | 每记录一个 `next` 字段 | 不移动记录本体；等关键字插入规则决定稳定性 |
| 希尔 | 依赖增量；教材给出一种序列为 $O(n^{3/2})$ | $O(1)$ | 不稳定；末增量必须为 1 |
| 起泡 | 正序 $O(n)$；平均、最坏 $O(n^2)$ | $O(1)$ | 仅交换严格逆序对时稳定 |
| 快速 | 随机排列平均 $O(n\log n)$；最坏 $O(n^2)$ | 普通双递归平均 $O(\log n)$、最坏 $O(n)$；短侧递归且长侧循环时保证 $O(\log n)$ | 不稳定；受枢轴和初态影响大 |
| 简单选择 | 各种初态均比较 $n(n-1)/2$ 次，$O(n^2)$ | $O(1)$ | 不稳定；记录移动少 |
| 树形选择 | $O(n\log n)$ | 线性量级选择树 | 复用比较信息，但有哨兵比较和存储开销 |
| 堆 | 平均、最坏 $O(n\log n)$ | $O(1)$ | 不稳定；最坏界有保证 |
| 2-路归并 | 平均、最坏 $O(n\log n)$ | $O(n)$ | 稳定；辅助记录空间最多 |
| 链式基数 | $O(d(n+rd))$ | $2rd$ 个桶指针，另有 $n$ 个链域 | 稳定；不基于记录间比较 |

教材的经验性比较是：在其讨论的同量级实现中，快速排序平均常数因子较小；$n$ 较大时归并排序常比堆排序省时，但要付出 $O(n)$ 辅助记录空间。这些是带实现环境的取舍，不是渐进式本身能够保证的绝对排序。

不存在对所有环境都最优的方法。选择时至少同时看记录数、初始有序程度、最坏界、辅助空间、记录大小、稳定性以及关键字能否分解；只比较一个渐进时间式不足以决定实现。

教材特别指出：基数排序适合 $n$ 很大而关键字位数、每位取值范围较小的情形。若关键字本身很大但多数记录的最高位已能彼此区分，可先按最高位分成较小子序列，再在各子序列内用直接插入排序。

### 大记录的地址排序（算法 10.18）

快速排序和堆排序不便直接改成表排序；记录很大时可另设地址向量。初始化 `adr[i]=i`，原算法中交换 `r[i]`、`r[j]` 的位置改为交换 `adr[i]`、`adr[j]`。排序后满足：`r[adr[i]]` 是第 $i$ 小记录。

若最终要求记录本体物理有序，就按置换环重排。算法 10.18 从位置 $i$ 出发，暂存 `r[i]`，沿 `adr` 指示的环把每个记录一次移到目标位置，并把已经到位的 `adr[j]` 置为 `j`：

```pseudo
for i = 1 .. n-1:
    if adr[i] != i:
        j = i
        r[0] = r[i]
        while adr[j] != i:
            k = adr[j]
            r[j] = r[k]
            adr[j] = j
            j = k
        r[j] = r[0]
        adr[j] = j
```

每个置换环只暂存一次，其余记录一次移动到位；一个非平凡环至少含两个记录，因此环数至多 $\lfloor n/2\rfloor$，记录移动总数至多 $\lfloor3n/2\rfloor$。

### 比较排序的判定树下界

当 $n$ 个关键字互不相同时，共有 $n!$ 种可能次序。任何只靠二元关键字比较区分这些次序的算法，都可表示为一棵二叉判定树：内部结点是一次比较，叶子是一个最终次序，从根到叶的边数就是该输入所需比较次数。

最小例：$n=3$ 时有 $3!=6$ 种次序，二叉判定树必须至少有 6 个叶子，因此必有一条路径含 $\lceil\log_2 6\rceil=3$ 次比较。

二叉树若有 $n!$ 个叶子，必有一条根到叶路径长度至少为

$$
\left\lceil\log_2(n!)\right\rceil.
$$

所以任一比较排序在最坏情况下至少比较 $\lceil\log_2(n!)\rceil$ 次。由斯特林公式，$\log_2(n!)=\Theta(n\log n)$，故比较次数的下界是 $\Omega(n\log n)$；堆排序、归并排序又给出 $O(n\log n)$ 的最坏上界，因此在“关键字互异、仅靠二元比较、考察最坏情况”的模型下，可达的最优数量级是 $\Theta(n\log n)$。原书此处用 $O(n\log n)$ 描述“下界”，方向不完整；下界、上界和紧确界应分别用 $\Omega$、$O$、$\Theta$。基数排序不只依赖记录间二元比较，不受同一判定树模型约束。

### 教材扩展：归并插入的比较次数

教材以 $F(n)$、$B(n)$、$M(n)$ 分别表示归并插入、折半插入、归并排序在最坏情况下的比较次数。Demuth 对 5 个数给出 7 次比较的方法，Ford 与 Johnson 将其推广为归并插入排序；原书表中 $F(n)$ 与判定树下界在 $1\le n\le11$ 时逐项相等，从 $n=12$ 起不再相等。这里采用表格能够直接核验的 $n\le11$，修正相邻正文印作 $n<11$ 的范围：

## 复习闭环

- 能否用“本趟结束后哪一段已经满足什么性质”描述直接插入、起泡、快速划分、选择、堆筛选、归并和基数分配的不变量？
- 能否区分“比较次数下降”与“总时间下降”，并解释折半插入为何仍可能是 $O(n^2)$？
- 能否从输入初态、枢轴位置、增量序列、桶数和关键字位数说明复杂度成立条件？
- 能否用含重复关键字的最小反例判断稳定性，而不是背诵笼统分类？
- 能否从 $n!$ 个叶子推出比较排序的 $\Omega(n\log n)$ 最坏下界，并说明基数排序为何不属于同一比较模型？
