# PRD｜文件系统生命周期沙盘

**版本**：v3

**产品形态**：一个独立页面、一套共享状态、一个人可慢慢操作的文件系统可视化沙盘。

**建议路由**：`/file-system-sandbox`

**一句话定义**：从“电脑刚开机，文件系统还没挂载”开始；用户每点一次启动、进入目录、新建文件、写入、同步、关闭、链接或删除，页面上的目录树、inode、位图、数据块、内存缓存和时间线都同步展示哪里变了、为什么变、先后顺序是什么。

---

## 1. 这次真正要解决的问题

不是做一组互不关联的文件系统插图，也不是让用户做题。要做的是一台可以观察内部状态的“小型教学文件系统”。

用户不必凭空记住：

- 启动后文件系统为什么能出现在 `/`；
- 文件名、目录项、inode、数据块分别在哪；
- 新建一个空文件时究竟改了哪些地方；
- 写入数据后为什么 inode、数据块位图、数据区、页缓存都会变化；
- `close`、`fsync`、`unlink` 的顺序为何不同；
- 两个硬链接、一个打开着的文件和删除操作如何共同决定何时真正回收空间。

她应该能自己操作并看到答案：**“这里先变、那里暂时不变、下一步才变。”**

## 2. 固定产品边界

### 要做

- 一页完整沙盘，所有组件始终围绕同一份教学文件系统状态。
- 覆盖文件管理、目录、文件系统中的全部现有知识点，但必须通过“状态 / 结构 / 操作”连接起来。
- 支持启动与挂载、文件生命周期、目录与链接、存储分配、空闲空间管理、VFS 与挂载。
- 允许反复播放、回退、重置和切换视角；不需要完成任何测试才能继续。

### 不做

- 不做题目、选择题、评分、闯关、排行榜、真题入口或错题功能。
- 不做真实磁盘操作，不读取或改动用户电脑上的文件。
- 不把这个教学模型伪装成某个操作系统或 ext4 的逐字节实现；所有实现相关差异都明确标为“教学简化模型 / 具体系统可能不同”。
- 不需要登录、云同步、多人协作或任何服务端个人数据。
- 不改写现有 `/knowledge/os/files` 原文；新页只链接回原文作延伸阅读。

## 3. 核心设计：一份状态，九个联动组件

页面不是按文章往下滚，而是一个“观察台”。用户发出操作，所有组件从同一份状态读取数据，因此永远不会出现目录树说文件存在、位图却没有变化的矛盾。

| 编号 | 组件 | 它显示什么 | 每次操作如何反馈 |
| --- | --- | --- | --- |
| 1 | 操作控制台 | 当前可执行的启动、挂载、文件、链接和分配操作 | 选择操作后生成可回退的事件序列 |

| 4 | 统一目录树 | 根目录、子目录、文件名、挂载点、硬链接与软链接 | 新增 / 移动 / 删除目录项立即高亮 |

## 4. 统一教学模型

### 4.1 默认磁盘状态

使用一个小而完整的虚拟磁盘，而不是用抽象占位文字：

- 一块磁盘含引导与分区元数据、一个根文件系统分区、一个可挂载的外部文件系统分区；
- 根文件系统分区包含超级块、inode 位图、数据块位图、inode 区和数据区；
- 根目录已有 `home/`、`tmp/`；`/home/mei/` 是操作案例的默认工作目录；
- 默认分配策略为“inode 的直接块 + 单级间接块”的简化混合索引；默认空闲空间管理为位图法；
- 所有编号、块大小、空闲状态和 inode 指针是固定、可复现且可测试的教学数据。

这个默认模型不是在宣称所有现实文件系统都这样逐项实现，而是用最少结构准确说明：**目录项、inode、数据块、空闲信息和内存对象怎样协作。**

### 4.2 两层状态必须分开

页面始终并列显示：

1. **持久化磁盘状态**：分区、超级块、位图、磁盘 inode、目录数据块、文件数据块；
2. **运行时内存状态**：已挂载超级块、活动 inode 缓存、fd 表、系统打开文件表、页缓存和脏页。

任何写入动作先在运行时层显示缓存 / 脏页变化；只有经过教学模型中的写回或 `fsync` 步骤，才在持久化磁盘层显示对应数据已落盘。`close` 只释放打开状态，不能被画成“已经确保写入磁盘”。

## 5. 主线 A：启动与根文件系统挂载

用户从“关机”状态开始。磁盘内容存在，内存视图为空，目录树不可浏览。

### 5.1 启动序列

默认提供两条可切换、但不混淆的路径：

| 路径 | 逐步展示 |
| --- | --- |
| BIOS / MBR | 固件自检与选择启动设备 → 读取 MBR → Bootloader 读取分区启动扇区 → 内核与初始化程序接管 |
| UEFI / GPT | UEFI 固件 → 读取 GPT 与 EFI 系统分区 → 加载 `.efi` 引导程序 → 内核与初始化程序接管 |

页面不需要讲完整硬件引导课程。它在“内核接管”后把镜头转到文件系统：

1. 内核识别根文件系统所在分区；
2. VFS 建立统一的文件访问入口；
3. 读取根分区的超级块，展示块大小、块数量和空闲空间管理方式；
4. 将根文件系统挂载到 `/`；
5. 首次访问 `/` 时，根目录相关 inode 进入活动 inode 缓存，目录树变为可浏览；
6. 页面提示：不是“所有 inode 和数据块在开机时全读入内存”，而是超级块等关键元数据建立可访问条件，其他对象按需进入缓存。

### 5.2 启动完成后的可见结果

- `VFS 挂载表` 中出现根文件系统与挂载点 `/`；
- 内存区出现已挂载的超级块和根目录相关活动 inode；
- 磁盘图不发生“新建文件”类变化，只高亮被读取 / 挂载的结构；
- 总览地图从“不可达”切换为“可从路径访问”。

## 6. 主线 B：新建、写入、同步、关闭与删除一个文件

默认故事对象为 `/home/mei/note.txt`。用户可以编辑名称和内容长度，但每个动作都保留同样清楚的底层顺序。

### 6.1 新建空文件：`create /home/mei/note.txt`

事件时间线必须逐步呈现：

1. **路径解析**：VFS 从 `/` 开始，逐级读取 `home`、`mei` 目录项，找到父目录 inode；路径解析器还可切换相对路径，并将 `.` 与 `..` 作为真实目录项展示；
2. **检查名称与权限**：确认父目录中没有同名目录项，且允许创建；
3. **分配 inode**：inode 位图中选定一位 `0 → 1`，inode 区新增 / 初始化对应 inode；
4. **创建目录项**：父目录的数据块新增 `note.txt → inode #n`；目录树显示新名字；
5. **初始化元数据**：新 inode 的类型、权限、所有者、大小 `0`、时间戳、链接计数 `1` 和空的数据块指针可见；
6. **保持数据区不变**：空文件尚未写入内容，不应凭空占用文件数据块；
7. **展示运行时与持久化边界**：教学模型先显示内存中的修改 / 待写回状态，再显示同步后落到磁盘 inode 与目录数据块的变化。

关键验收点：操作结束后，目录树、目录项、inode 位图、inode 区都变了；数据块位图和数据区没有因“空文件”而变化。

### 6.2 打开并写入：`open → write → fsync → close`

#### `open(note.txt)`

1. 路径解析得到 inode；
2. inode 进入或命中活动 inode 缓存；
3. 系统打开文件表新增一项，包含打开模式、当前偏移 `0`、inode 引用和引用计数；
4. 当前进程 fd 表选一个空闲整数指向该打开文件表项；
5. 变化清单明确说明：此时目录项、磁盘数据块和文件大小都没有改变。

#### `write(fd, data)`

1. 用户缓冲区的数据进入页缓存；相应页标记为脏；
2. 若文件需要新空间，空闲空间管理器选择数据块：默认位图对应位 `0 → 1`；
3. inode 的数据块指针、文件大小和修改时间更新；
4. 若文件超过直接块容量，展示进入单级间接索引块的完整路径；
5. 系统打开文件表中的当前偏移向前移动；
6. 目录项不变化，fd 编号不变化；
7. 持久化磁盘视图保持“等待写回 / 脏”提示，直到发生同步。

#### `fsync(fd)`

1. 选择与该文件有关的脏页、inode 更新和必要元数据；
2. 依次显示写回路径：页缓存 → 文件数据块 / inode 区 / 位图 / 目录数据块；
3. 清除相应“脏”标识；
4. 持久化磁盘视图显示最终状态。

#### `close(fd)`

1. 进程 fd 表删除这一项；
2. 系统打开文件表引用计数减一，归零时回收该运行时表项；
3. inode 是否留在活动缓存由缓存策略决定，不强行画成必定消失；
4. 明确提示：`close` 不是持久化保证，`fsync` 才是本沙盘中的明确同步动作。

### 6.3 读取与定位：`read`、预读取、`lseek`

- `read` 显示逻辑块号如何经 inode 指针 / 索引块找到数据块；命中页缓存时不访问持久化数据区，未命中时再读取数据块。
- 顺序读取时以浅色预览后续页进入页缓存；用户可关闭“显示预读取”以比较前后差异。
- `lseek` 只改变系统打开文件表中的当前偏移；不直接分配数据块，不搬运文件内容。

### 6.4 硬链接、软链接与删除：`link / symlink / unlink`

#### 硬链接

- 新增一个目录项，指向既有 inode；
- inode 链接计数增加；
- 不新增文件数据块、不复制内容、不创建新 inode；
- 页面标出硬链接不能跨文件系统、不能指向目录。

#### 软链接

- 新增独立 inode 与目录项；
- 为软链接自身分配保存“目标路径字符串”的数据块 / 教学存储；
- 展示访问软链接时先读路径字符串、再重新解析目标路径；
- 删除目标后，软链接仍存在但变为悬挂链接；可跨文件系统，也可链接目录。

#### 删除与延迟回收

默认提供“文件仍被进程打开”场景，时间线必须展示：

1. `unlink` 移除父目录中的目录项；
2. inode 链接计数减一；
3. 若链接计数为 `0` 但系统打开文件表仍有引用，inode 和数据块暂不释放；
4. 最后一个 `close` 后，才清空 inode 位图、数据块位图、inode 区和数据区的对应占用；
5. 目录树中名字消失的时刻与物理空间被回收的时刻被清楚区分。

### 6.5 目录操作的同构演示

操作控制台还提供 `mkdir`、重命名和移动三个不评分动作。它们复用同一份状态和变化清单：

- `mkdir` 分配目录 inode、创建父目录中的目录项，并在新目录内容中展示 `.` 与 `..`；
- 重命名只改变相应目录项的名字；
- 同一文件系统内移动体现为源目录项删除、目标目录项新增，inode 与数据块不复制；
- 所有操作均显示权限检查、父目录变化以及是否跨越挂载点，避免把“移动文件”误理解为一定复制所有数据块。

## 7. 主线 C：同一文件如何被组织与分配

这是沙盘的“结构切换”视图，不会把不同实际文件系统策略混为一个运行状态。用户可把当前 `note.txt` 的逻辑块映射复制到不同模型中比较。

在物理分配面板上方，先显示“逻辑记录视图”：顺序文件按记录次序读取；随机 / 直接文件可根据记录号或关键字直接定位。这个面板只解释用户 / 程序看到的数据组织，不把它和磁盘块的物理分配混为一谈。

| 分配模型 | 必须可观察的变化与顺序 |
| --- | --- |
| 连续分配 | 目录 / inode 保存起始块与长度；扩展时寻找连续区段；外部碎片与末块内部碎片可见 |
| 链式分配 | 每个数据块保存下一块号；访问逻辑块 k 必须从头逐跳；指针损坏影响后续链 |
| FAT | 目录保存起始块；FAT 中的后继块号变化，块中不再放隐式 next 指针 |
| 一级 / 多级索引 | inode / 目录指向索引块；逻辑块号沿索引路径到达数据块；容量取决于块大小与指针大小 |
| 混合索引 | 小文件使用直接块；越过阈值后进入单、双、三级间接块；它优化索引开销而不承诺消除外部碎片 |

用户每次调节文件大小或访问逻辑块号，`数据块与分配视图`、`inode 视图` 和 `变化清单` 一起更新。没有“最优答案”提示，只展示各结构真实的寻址与空间代价。

## 8. 主线 D：同一批空闲块如何被管理

在默认运行时模型中使用位图法；用户可在独立的“空闲空间策略”视图复刻同一个分配 / 回收操作，观察其他三种方法会怎样记账。

| 方法 | 沙盘必须显示 |
| --- | --- |
| 空闲表法 | 每行的起始空闲盘块号与连续空闲块数；分配导致区段缩短 / 分裂，回收可能合并 |
| 空闲链表法 | 链表头、块内 next 指针、取头分配、头插回收；连续块查找与全盘统计的代价 |
| 位图法 | bit 与盘块一一对应；找 `0`、置 `1`、回收置 `0`；位图属于持久化元数据 |
| 成组链接法 | 内存空闲块号栈、当前组、组空时从盘块补组、组满时把一组号码写回新回收块；组间单向连接 |

每一种策略的图均从完全相同的盘块占用状态开始，以防用户把差异误认为来自不同输入。

## 9. VFS 与挂载：为什么多块盘能出现在一棵目录树里

在根文件系统已挂载的状态下，用户可以选择一个外部文件系统分区并挂载到 `/mnt/usb`：

1. 系统识别分区与对应文件系统；
2. VFS 根据挂载请求找到具体文件系统实现；
3. 外部文件系统的根目录挂接到既有目录树的挂载点；
4. 挂载点原有内容在挂载期间被暂时遮蔽；
5. 从 `/mnt/usb/photo.jpg` 访问时，路径解析跨越挂载点并由对应文件系统处理；
6. 卸载后外部树分离，原挂载点内容重新可见。

同一面板还应显示 `open/read/write/close` 进入 VFS 后如何被分派给 ext4、NTFS、NFS、ISO 9660 等具体实现，强调 VFS 的统一接口、可扩展性与可移植性。

## 10. 单人操作体验

- 顶部只有当前状态、重播、上一步、下一步、重置和“跳到结构”控件；没有任务列表、得分或完成率。
- 每个操作先显示简短自然语言描述，例如“新建一个空文件：会占用 inode，但暂时不占用数据块”。

### 不可违背的表述

- 文件名在目录项中，inode 保存文件元数据和数据块地址。
- 进程 fd 表、系统打开文件表、活动 inode 缓存、磁盘 inode 区是不同层次。
- 独立的 `open` 通常有独立打开文件对象与偏移；`dup` / `fork` 才可能共享。
- `close` 不等于已经持久化；延迟写 / 页缓存与 `fsync` 的边界必须可见。
- 逻辑文件结构、物理分配方式和空闲空间管理方式是不同维度，不能混称。
- MBR / BIOS 与 GPT / UEFI 是两条不同启动路径；GPT 不能说成 MBR 的分区表。
- 超级块是挂载与文件系统管理的关键元数据；不应表述成启动时把所有文件数据与 inode 全部读入内存。
- inode 链接计数为零且没有进程继续打开时，才回收对应 inode 与数据块。

## 13. 验收标准

### 端到端主案例必须成立

**关机 → 启动 → 挂载 `/` → 新建 `note.txt` → 打开 → 写入 → `fsync` → 关闭 → 创建硬链接 → `unlink` → 最后关闭 → 回收**，每一步均可前后回退，且状态一致。

| 操作 | 必须可见的变化 |
| --- | --- |
| 启动并挂载根文件系统 | VFS 挂载表、超级块内存对象、根目录可访问；不伪造“所有文件已载入” |
| 新建空文件 | 父目录新增目录项、inode 位图与 inode 区变化；数据块位图与数据区保持不变 |
| `open` | 当前进程 fd 表、系统打开文件表、活动 inode 缓存变化；文件数据和目录项不变 |
| `write` | 页缓存 / 脏页、偏移、inode 大小 / 指针、数据块位图与数据块映射变化；目录项不变 |
| `fsync` | 脏页和相关元数据由运行时层同步到持久化磁盘层 |
| `close` | fd 与打开文件表引用变化；不把它误画成强制落盘 |
| 硬链接 | 新目录项 + inode 链接计数增加；不新增 inode / 文件数据块 |
| 软链接 | 新目录项、独立 inode、目标路径字符串；目标删除后显示悬挂状态 |
| `unlink` 但仍打开 | 名字消失、链接计数变化；inode 与数据块暂不回收 |
| 最后一个 `close` | inode 位图、数据块位图、inode 区、数据区对应空间同时释放 |

### 完整知识点覆盖

- 所有原始文件管理、目录、文件系统页面的二级 / 三级知识点都可从至少一个组件或状态操作进入。
- 连续、链式、FAT、索引、多级、混合索引以及空闲表、空闲链表、位图、成组链接法均有同输入下的可视化状态变化。
- 目录树、路径解析、硬链接、软链接、VFS、挂载、MBR / GPT 与超级块均不是孤立插图，而是能接入主状态模型或与其进行明确对照。

### 工程质量

- 文件系统状态转换使用纯函数与可重放事件日志；每个事件的前后状态可做断言。
- 自动化测试覆盖：路径解析、inode 分配 / 回收、fd / 打开文件表共享关系、位图分配、写回、`unlink` 延迟回收、索引寻址与挂载树接合。
- 通过项目构建、静态检查和桌面 / 360 px 窄屏可视验收。
- 不读取真实系统文件，不执行真实 `mount`、`rm`、`fsync` 或任何破坏性操作。
