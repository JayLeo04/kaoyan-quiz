# 优化 408 知识页

把原始 Markdown 当作唯一内容源与不可丢失基线；`app/data/knowledge*.json` 与 `public/knowledge/` 都是生成物，绝不直接编辑。

## 0. 不可妥协的三条原则

- 保留原始 Markdown 中的定义、推导、例题、代码、表格、链接、图片语义和考点覆盖；只能增量修复结构、措辞错误或呈现，不能把长文压缩成摘要、以新内容覆盖旧内容，或因美化而删去知识信息。
- 在改动前后审阅源文件差异；除明确的乱码、重复内容或用户认可的错误外，不接受知识性正文的删除。若必须停止渲染旧图，保留其来源或“旧资源 → 新呈现”的可追溯记录，并确认新呈现完整保留原图信息。
- 先让正文无需交互也能讲清结论、概念和步骤，再添加视觉补充。只有图能显著降低理解成本时才添加；一张图或一个交互只服务一个核心结论，不用装饰性、文字堆叠或需要反复猜测含义的可视化。

## 本轮复盘：高频问题与有效解法

- 将“章节顺序混乱”先定位为导入器建模问题：从父级 `index.md` 的直接链接生成顺序，而非按文件名排序；随后只重新导入受影响科目。
- 将“没有表格、只有长文本”“子标题高度不合适”先还原为 Markdown 结构问题：使用真实表格、列表与层级标题，避免用缩进和加粗承担结构语义。
- 将银行家算法、资源分配图、生产者—消费者和哲学家就餐等过程性知识改为可调参数、可逐步推进、可回看代码高亮的交互；让图负责状态变化，正文负责完整解释。
- 将旧 SVG 的“丑”拆成可验证标准：新交互必须覆盖旧图的标签、方向、状态与结论，才移除旧资源；以当前页面 DOM 的实际 `img[src]` 为准，不以 SSR 页面源码中同科数据的残留为准。
- 将“首页卡片显示不全”作为容器高度与溢出问题验收：同时检查 `scrollHeight`、`clientHeight`、桌面和窄屏，而非仅看单一截图。
- 将本地服务需求与页面修复分开处理：用 LaunchAgent 的 `RunAtLoad`、`KeepAlive` 和 `127.0.0.1:3001` 绑定实现开机常驻，不绑定当前对话或外网部署。

## 1. 定位与建立基线

1. 对用户给出的 URL 运行：

   ```bash
   node .codex/skills/review-408-page-by-url/scripts/resolve-page.mjs --json '<URL>'
   ```

2. 在浏览器查看目标页的顶部、中段、底部和窄屏；完整阅读对应 `index.md`、同目录 `assets/`、父级 `index.md` 与该科 `_visualizations.json`。
3. 先区分问题属于原文语义、导入器顺序、共享渲染组件、CSS，还是未重新导入的旧生成数据；不要凭截图猜测源文件。
4. 同时遵守 `preserve-408-markdown`、`repair-408-knowledge-pages`；需要交互时遵守 `build-408-interactive-knowledge-visuals`。

## 2. 按学习路径组织章节

- 子章节顺序以父级 `index.md` 中的直接链接为准，不按文件名字典序或目录深度猜测。
- 在导入器中从父页直接链接推导顺序；同一页多个交互 spec 必须按 Markdown marker 的出现顺序输出。
- 修改导入器后，对受影响科目定向重新导入：

  ```bash
  npm run knowledge:408 -- --subject ds|co|os|cn
  ```

- 若测试发现源清单存在、生成数据却缺失，先定向导入对应科目；不要只放宽测试。不要为了刷新顺序而导入一个尚未通过本身公式/可视化审计的无关科目。

## 3. 恢复正文层次与页面节奏

- 对比项使用真正的 Markdown 表格；枚举使用列表；不要以连续缩进段落伪造表格或项目符号。
- 用准确的 `##`、`###`、`####` 表达定义、机制、算法步骤和例外，避免把“银行家算法”“绝对装入”等应有小节写成普通加粗段落。
- 采用“先结论/定义、后机制/步骤、再例子或边界”的阅读节奏；给术语必要的短解释，但不以口号或泛泛比喻替代严谨表述。
- 保留原有定义、推导、例题和有效图片；只作增量修复，不把长文压缩成摘要。正文中相同信息可通过标题、表格、列表重组得更易读，但不得减少其可获得的信息。
- 调整公共标题间距或图文布局时，检查桌面和窄屏，避免新增全局溢出或裁切。

## 4. 用简洁交互补充理解，同时保留信息

- 默认保留原图与正文说明。低质量、文字堆叠的旧图只有在新交互覆盖其关键标签、方向、状态和结论后，才可停止在当前页渲染；记录“旧资源 → 新 visual ID”，不让知识信息随资源替换消失。
- 在 Markdown 的原语义位置保留唯一标记：

  ```md
  <!-- knowledge-visual:os-example-purpose -->
  ```

- 在本科 `_visualizations.json` 保存所有步骤、公式、数值和说明；公共 React 组件只实现通用图型。让每个视觉有明确标题、一个主结论、少量必要标签和紧邻的文字说明。
- 为过程性内容选择适合的图型：

  | 知识关系 | 必备交互 |
  | --- | --- |
  | 银行家算法 | 可编辑 Available / Max / Allocation；Need 自动计算；逐步展示 Work、回收和安全序列。 |
  | 资源分配图 | 至少提供单实例与多实例两例；显示请求/分配箭头及“有环”判定边界。 |
  | 信号量同步 | 逐步展示缓冲区或资源归属、信号量状态、当前行为和高亮代码行。 |

- `sourceLatex` 必须与 Markdown 中完整定界的 LaTeX 一致；不把公式、代码或正文硬编码进共享组件。
- 折叠代码使用原生 `<details>`，默认收起。图中只保留理解图形所必需的简短标签，详细说明放在可访问的正文或交互状态中；若表格或列表已能更清楚说明关系，就不要额外造图。

## 5. 处理“页面仍命中旧资源”的假象

- 先在当前页面 DOM 查询具体的 `img[src]`，再判断旧资源是否仍被显示。
- SSR HTML 可能序列化同科其他页面的数据；原始 HTML 中出现同名 `inline-svg-06.svg` 不等于目标页仍在使用该图。
- 在原文、生成页数据和实际 DOM 均不引用后，才删除孤立旧资源；重新导入对应科目以清除 public 副本。


然后在浏览器逐项检查：

- 原始 Markdown 的差异中没有未经授权的知识性删除，标题、公式、表格、例题、链接与图片语义仍完整；
- 父级目录、侧栏和上一篇/下一篇顺序；
- 表格、标题、公式、图片和移动端不溢出；
- 数字输入、下一步/上一步、资源图切换、代码高亮和折叠代码；
- 不操作交互也能从正文理解要点；视觉不堆叠大段文字、不重复正文，也不依赖颜色作为唯一信息来源；
- 被替换旧图不再出现在当前 DOM；
- 数据面板的 `scrollHeight` 不大于 `clientHeight`，没有隐藏内容。

如果用户要求本地常驻服务，确认 LaunchAgent 使用 `RunAtLoad` 与 `KeepAlive` 并绑定 `127.0.0.1`；不要擅自部署外网。
