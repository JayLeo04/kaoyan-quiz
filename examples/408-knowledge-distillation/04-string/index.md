# 第 4 章 串

> **📌 本章主线**
>
> 串是元素受限为字符的线性序列，但基本操作通常以整个串或子串为对象。复习时先固定“位序从 1 开始、匹配失败返回 0”的教材约定，再串联三条主线：三种存储表示、朴素匹配与 KMP、串操作在文本和索引中的组合应用。

> **🎯 408 复习定位**
>
> 需要能区分空串与空格串，判断串操作的合法区间和截断结果；能说明三种存储表示的字段与取舍；能手算 `next`/`nextval`，写出朴素匹配、KMP 及 `get_next` 的关键分支，并说明复杂度成立的条件。

## 本章知识地图

- **逻辑层**：字符有限序列 → 子串、主串、位置、相等 → 13 个抽象操作与最小操作子集。
- **存储层**：定长顺序存储受上界约束；堆分配按实际串长申请连续空间；块链存储以结点成块保存字符。
- **算法层**：朴素匹配在失配时回退主串指针；KMP 保持主串指针不回退，只按模式串的 `next` 链回退。
- **应用层**：文本编辑用页表、行表管理子串映像；关键词索引用“有序关键词表 + 书号链表”组织一对多关系。

## 4.1 串的逻辑定义与抽象操作

<!-- source: section="4.1" source_file="4-1-string-definition/index.md"
     pdf_pages="80-82" book_pages="70-72" items="式(4-1), 算法4.1" -->

### 定义、位置与相等

**串（字符串）**是由零个或多个字符组成的有限序列：

$$
s='a_1a_2\cdots a_n'\qquad(n\ge 0)
\tag{4-1}
$$

其中 $s$ 是串名，单引号内是串值，$a_i\ (1\le i\le n)$ 来自字符集，$n$ 是串长；单引号只作定界，不属于串值。

按抽象数据类型写法，数据对象与相邻关系分别为：

$$
D=\{a_i\mid a_i\in CharacterSet,\ i=1,2,\ldots,n,\ n\ge 0\},
\qquad
R_1=\{\langle a_{i-1},a_i\rangle\mid a_{i-1},a_i\in D,\ i=2,\ldots,n\}
$$

- $n=0$ 时为空串，记作“∅”。
- 由一个或多个空格组成的是**空格串**，其长度等于空格数，不是空串。
- 串中任意个连续字符组成的子序列是**子串**，包含它的串是**主串**。
- 字符的位置是它在序列中的位序；子串的位置取其首字符在主串中的位序。
- 两串相等当且仅当长度相等，且每个对应位置的字符都相等。

最小例：`'BEIJING'` 长 7，`'BEI JING'` 长 8；`'JING'` 在二者中的位置分别为 4 和 5。空格是串值的一部分，因此两主串不相等。

串与线性表都具有线性逻辑结构；区别是串的元素被限制为字符，且线性表操作多针对单个元素，串操作多针对整个串或连续子串。

### 抽象操作及其边界

| 操作 | 前置条件 | 结果 |
| --- | --- | --- |
| `StrAssign(&T, chars)` | `chars` 是字符串常量 | 生成值为 `chars` 的串 `T` |
| `StrCopy(&T, S)` | `S` 存在 | 复制 `S` 得到 `T` |
| `StrEmpty(S)` | `S` 存在 | 空串返回 `TRUE`，否则返回 `FALSE` |
| `StrCompare(S, T)` | `S`、`T` 存在 | 分别以正数、0、负数表示 `S>T`、`S=T`、`S<T` |
| `StrLength(S)` | `S` 存在 | 返回串长 |
| `ClearString(&S)` | `S` 存在 | 将 `S` 清为空串 |
| `Concat(&T, S1, S2)` | `S1`、`S2` 存在 | `T=S1+S2` |
| `SubString(&Sub, S, pos, len)` | $1\le pos\le \lvert S\rvert$，$0\le len\le \lvert S\rvert-pos+1$ | 返回从第 `pos` 个字符起、长为 `len` 的子串 |
| `Index(S, T, pos)` | `T` 非空，$1\le pos\le \lvert S\rvert$ | 从 `S` 的第 `pos` 个字符起找 `T` 的首次出现位置；失败返回 0 |
| `Replace(&S, T, V)` | `T` 非空 | 用 `V` 替换 `S` 中所有与 `T` 相等且互不重叠的子串 |
| `StrInsert(&S, pos, T)` | $1\le pos\le \lvert S\rvert+1$ | 在 `S` 的第 `pos` 个字符之前插入 `T` |
| `StrDelete(&S, pos, len)` | 教材给出的条件为 $1\le pos\le \lvert S\rvert-len+1$ | 删除从第 `pos` 个字符起、长为 `len` 的子串 |
| `DestroyString(&S)` | `S` 存在 | 销毁 `S` |

`StrAssign`、`StrCompare`、`StrLength`、`Concat`、`SubString` 构成教材给出的**最小操作子集**：它们不能由其余串操作组合得到；除 `ClearString`、`DestroyString` 外，其余操作可在这个子集上实现。

> **🧭 条件与边界**
>
> 本章接口使用 1 起始位序。`SubString` 允许 `len=0`，但仍要求 `pos` 落在 $1\ldots \lvert S\rvert$；`Index` 和 `Replace` 都要求模式串 `T` 非空；`Replace` 只处理互不重叠的匹配。

### 算法 4.1：用基本操作实现定位

令 $n=\lvert S\rvert$、$m=\lvert T\rvert$。从 `i=pos` 到 `n-m+1`，依次取长为 $m$ 的子串并与 `T` 比较：

```text
Index(S, T, pos):                 // T 非空
    if pos <= 0: return 0
    n <- StrLength(S); m <- StrLength(T)
    i <- pos
    while i <= n - m + 1:
        sub <- SubString(S, i, m)
        if StrCompare(sub, T) == 0: return i
        i <- i + 1
    return 0
```

算法的不变量是：进入第 `i` 次比较前，所有起点位于 `[pos, i-1]` 的候选子串都已被排除。每个候选都要复制 $m$ 个字符并进行比较，因此代价由候选起点数和模式串长度共同决定。

## 4.2 串的存储表示与实现

<!-- source: section="4.2" source_file="4-2-string-representation-and-implementation/index.md"
     pdf_pages="82-89" book_pages="72-79" items="算法4.2-4.4, 图4.1-4.2" -->

三种表示都保存同一逻辑串，但串长上界、空间分配和操作成本不同：

| 表示 | 核心布局 | 空串表示 | 主要约束与取舍 |
| --- | --- | --- | --- |
| 定长顺序存储 | 固定数组；教材约定 `S[0]` 存长度，`S[1..S[0]]` 存字符 | `S[0]=0` | 地址连续、复制方便；超过 `MAXSTRLEN` 时按约定截尾 |
| 堆分配存储 | `ch` 指向按实际长度分配的连续区，另存 `length` | `ch=NULL, length=0` | 不预设串长上界；修改长度常需重新分配和搬移字符 |
| 块链存储 | 多个字符块以单链表连接，另存 `head`、`tail`、`curlen` | 长度为 0，头尾指针按实现约定 | 便于连接、适合长串；有指针开销、尾块填充和跨块处理成本 |

### 4.2.1 定长顺序存储

教材采用长度显式存放的结构：

```c
#define MAXSTRLEN 255
typedef unsigned char SString[MAXSTRLEN + 1];
/* S[0] 为实际长度，字符位于 S[1..S[0]] */
```

另一种格式是在串值后放不计入串长的终止字符 `\0`。前者读取串长可直接访问长度单元；后者的串长是隐含值，某些操作需要扫描才能得到。

#### 算法 4.2：定长串联接

设 $M=\texttt{MAXSTRLEN}$，`T=Concat(S1,S2)` 的结果分三种：

| 条件 | `T` 的内容 | 返回值 |
| --- | --- | --- |
| $\lvert S1\rvert+\lvert S2\rvert\le M$ | 完整复制 `S1` 与 `S2` | `TRUE` |
| $\lvert S1\rvert<M<\lvert S1\rvert+\lvert S2\rvert$ | 完整 `S1` 加 `S2` 的前 $M-\lvert S1\rvert$ 个字符 | `FALSE` |
| $\lvert S1\rvert=M$ | `T=S1`，`S2` 全部被截去 | `FALSE` |

```text
if S1[0] + S2[0] <= M:
    copy S1; copy all S2; T[0] <- S1[0] + S2[0]; return TRUE
else if S1[0] < M:
    copy S1; copy S2[1..M-S1[0]]; T[0] <- M; return FALSE
else:
    copy S1[0..M] to T; return FALSE
```

正确性要点是先按条件决定可写入的 `S2` 长度，再设置 `T[0]`；不能只写字符而遗漏长度。按字符复制计，时间随实际写入的 `T` 长度线性增长，且最多写入 $M$ 个字符。

#### 算法 4.3：定长串求子串

```text
SubString(Sub, S, pos, len):
    if pos < 1 or pos > S[0] or len < 0 or len > S[0] - pos + 1:
        return ERROR
    Sub[1..len] <- S[pos..pos+len-1]
    Sub[0] <- len
    return OK
```

合法时只复制 `len` 个字符，时间为 $O(len)$；`len=0` 时结果为空串。该操作本身不会截断，因为合法性条件已保证所取范围位于 `S` 内。

定长表示的共同原操作是字符序列复制。联接、插入或替换产生的结果超过上界时，教材统一采用截尾约定；题目若改变溢出策略，结果也会改变。

### 4.2.2 堆分配存储

```c
typedef struct {
    char *ch;   /* 非空串的首地址；空串为 NULL */
    int length;
} HString;
```

核心操作仍是字符复制，但空间按实际串长动态申请；字符区只按 `length` 个单元分配，不依赖 `\0` 终止符：

- `StrAssign`/`StrCopy`：先释放目标串旧空间；`StrAssign` 扫描以 `\0` 结束的 `chars` 求长度；源串非空时申请等长空间并复制，源串为空时令 `ch=NULL, length=0`。
- `StrLength`：直接返回结构中的 `length`。
- `StrCompare`：逐字符比较共同前缀；遇到首个不同字符即返回其差值，共同前缀完全相同时以长度差决定结果。
- `ClearString`：释放 `ch`，再置 `ch=NULL, length=0`。
- `Concat`：释放 `T` 旧空间，申请 $\lvert S1\rvert+\lvert S2\rvert$ 个字符单元，先后复制两串并更新长度。
- `SubString`：先做与算法 4.3 相同的合法性检查；`len=0` 时返回空串，否则申请 `len` 个单元并复制。

> **🔎 源文/转写疑点**
>
> 4.2.2 的模块原型把 `SubString` 写成“返回 `HString`”，随后实现却采用“`Status` 返回码 + `Sub` 输出参数”。两处对合法区间和结果含义一致；本页按后者说明算法行为，不把原片段当作可直接编译的统一接口。

#### 算法 4.4：堆串插入

前置条件为 $1\le pos\le \lvert S\rvert+1$。以下 $\lvert S\rvert$ 均指插入前的原串长度；若 `T` 为空，`S` 不变，否则：

1. 把 `S` 的空间扩为 $\lvert S\rvert+\lvert T\rvert$ 个字符单元。
2. 从原串尾部向前移动 `S[pos-1..S.length-1]`，为 `T` 腾出连续空间。
3. 把 `T[0..T.length-1]` 复制到 `S[pos-1..pos+T.length-2]`。
4. 令 `S.length <- S.length + T.length`。

从后向前移动是不变量所需的更新顺序：每次写入右侧新位置时，尚未移动的源字符不能被覆盖。不计动态分配器内部代价，字符移动与复制量为 $(\lvert S\rvert-pos+1)+\lvert T\rvert$，因此时间为 $O(\lvert S\rvert-pos+1+\lvert T\rvert)$。

### 4.2.3 块链存储

```c
#define CHUNKSIZE 80
typedef struct Chunk {
    char ch[CHUNKSIZE];
    struct Chunk *next;
} Chunk;
typedef struct {
    Chunk *head, *tail;
    int curlen;
} LString;
```

每个结点可放一个或多个字符。若尾结点未装满，教材以不属于串字符集的 `#` 等特殊字符填充空位；`curlen` 才决定哪些位置属于串值，填充字符不计入串长。

$$
\text{存储密度}=\frac{\text{串值所占的存储位}}{\text{实际分配的存储位}}
$$

| 结点大小 | 优点 | 代价 |
| --- | --- | --- |
| 1 个字符 | 单字符处理直接，不存在块内空位 | 每字符都附带链域，存储密度低，内外存交换次数可能增多 |
| 多个字符 | 指针开销被多个字符分摊，存储密度通常更高 | 尾块可能浪费；插入、删除、联接要处理块内位置和无效填充 |

通常只需从头向尾扫描，所以单链即可；`tail` 用于加速联接，但联接前必须处理第一个串尾块的无效字符。字符集大小也会影响字符编码长度，进而影响合适的块大小和存储方式。

## 4.3 串的模式匹配

<!-- source: section="4.3" source_file="4-3-string-pattern-matching-algorithms/index.md"
     pdf_pages="89-94" book_pages="79-84" items="式(4-2)-式(4-12), 算法4.5-4.8, 图4.3-图4.6, 原书p94未编号表" -->

设主串 $S=s_1s_2\cdots s_n$，模式串 $T=p_1p_2\cdots p_m$，`T` 非空，$1\le pos\le n$。目标是返回 `T` 从主串第 `pos` 个字符起第一次出现的位序；不存在时返回 0。

### 4.3.1 朴素模式匹配

#### 算法 4.5：直接逐字符匹配

```text
Index(S, T, pos):
    i <- pos; j <- 1
    while i <= S[0] and j <= T[0]:
        if S[i] == T[j]:
            i <- i + 1; j <- j + 1
        else:
            i <- i - j + 2
            j <- 1
    if j > T[0]: return i - T[0]
    return 0
```

比较 `S[i]` 与 `T[j]` 前，当前候选起点是 $i-j+1$，并且该起点后的前 $j-1$ 个字符已经匹配。失配时 `i <- i-j+2`，恰好把候选起点右移一位，`j` 回到 1；成功时 `i` 已指向匹配段后一位，所以起点为 $i-m$。

算法 4.1 与算法 4.5 的候选起点推进相同；前者通过 `SubString`、`StrCompare` 组合实现，后者直接控制两个字符指针。

在部分匹配很少的输入上，实际比较次数可接近 $O(n+m)$；最坏情况下，每个候选起点都可能比较接近 $m$ 个字符，时间为 $O(nm)$。教材的最坏情形例是模式 `'00000001'` 与“前 52 个字符均为 `0`、随后为 `1`”的主串：多趟都到模式末尾才失配，主串指针反复回溯。

### 4.3.2 KMP：主串指针不回溯

KMP 在失配时保留主串指针 $i$，只利用已经匹配的模式前缀信息调整 $j$。关键问题是：当 $s_i\ne p_j$ 时，模式中哪个字符应再次与 $s_i$ 比较。

#### 失配回退的前缀—后缀条件

若下一次应比较 $s_i$ 与 $p_k\ (k<j)$，则已经匹配的主串后缀必须同时等于模式前缀：

$$
p_1p_2\cdots p_{k-1}=s_{i-k+1}s_{i-k+2}\cdots s_{i-1}
\tag{4-2}
$$

此前的部分匹配又给出：

$$
p_{j-k+1}p_{j-k+2}\cdots p_{j-1}=s_{i-k+1}s_{i-k+2}\cdots s_{i-1}
\tag{4-3}
$$

消去共同的主串片段，得到只依赖模式串的条件：

$$
p_1p_2\cdots p_{k-1}=p_{j-k+1}p_{j-k+2}\cdots p_{j-1}
\tag{4-4}
$$

因此，教材的 1 起始 `next` 定义为：

$$
next[j]=
\begin{cases}
0, & j=1,\\
\operatorname{Max}\{k\mid 1<k<j,\ p_1\cdots p_{k-1}=p_{j-k+1}\cdots p_{j-1}\},
& \text{集合非空},\\
1, & \text{其他情况}。
\end{cases}
\tag{4-5}
$$

`next[j]=k` 的操作含义是：`p_j` 失配后，让当前主串字符改与 `p_k` 比较。`next[1]=0` 是哨兵；当 `j` 回退到 0 时，当前主串字符与模式首字符也无法匹配，下一步同时令 `i`、`j` 加 1。

模式 `'abaabcac'` 的教材示例如下：

| $j$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| $p_j$ | a | b | a | a | b | c | a | c |
| $next[j]$ | 0 | 1 | 1 | 2 | 2 | 3 | 1 | 2 |

#### 算法 4.6：KMP 匹配

```text
Index_KMP(S, T, pos, next):
    i <- pos; j <- 1
    while i <= S[0] and j <= T[0]:
        if j == 0 or S[i] == T[j]:
            i <- i + 1; j <- j + 1
        else:
            j <- next[j]
    if j > T[0]: return i - T[0]
    return 0
```

| 当前状态 | 转移 | 保持的事实 |
| --- | --- | --- |
| `S[i]==T[j]` | `i++，j++` | 已匹配前缀延长 1 个字符 |
| `S[i]!=T[j]` 且 `j>0` | `j=next[j]` | `i` 不变；式（4-4）保证回退后无需重比已知相等部分 |
| `j==0` | `i++，j++` | 排除当前主串字符作为匹配起点，转到下一字符 |
| `j>T[0]` | 返回 `i-T[0]` | 模式全部匹配 |
| `i>S[0]` 且未成功 | 返回 0 | 主串剩余部分不足以继续匹配 |

以源图 4.5 的主串 `acabaabaabcacaabc`、模式 `abaabcac` 为最小轨迹：

| 比较状态 | 结果与转移 |
| --- | --- |
| `i=1,j=1` | `a=a`，推进到 `i=2,j=2` |
| `i=2,j=2` | `c≠b`，令 `j=next[2]=1`，`i` 不变 |
| `i=2,j=1` | `c≠a`，先令 `j=0`；哨兵分支再推进到 `i=3,j=1` |
| `i=3..8,j=1..6` | 前 5 个字符匹配，在 `s_8=a` 与 `p_6=c` 处失配；令 `j=next[6]=3`，`i=8` 不变 |
| `i=8..13,j=3..8` | 其余字符全部匹配，结束时 `i=14,j=9`，返回 $14-8=6$ |

整个过程中主串指针只向右移动，模式指针沿 `next` 链回退。预处理模式并完成匹配的总时间为 $O(n+m)$；不回读主串的性质尤其适合边读入边匹配的外部数据。

#### 算法 4.7：递推求 `next`

基例为：

$$
next[1]=0
\tag{4-6}
$$

设 $next[j]=k$，则已有最长前缀—后缀关系：

$$
p_1\cdots p_{k-1}=p_{j-k+1}\cdots p_{j-1}
\tag{4-7}
$$

若 $p_k=p_j$，关系可同时向右扩展一位：

$$
p_1\cdots p_k=p_{j-k+1}\cdots p_j
\tag{4-8}
$$

于是：

$$
next[j+1]=next[j]+1
\tag{4-9}
$$

若 $p_k\ne p_j$，令 $k'=next[k]$ 并沿 `next` 链继续找更短候选。若某次有 $p_j=p_{k'}$，则：

$$
p_1\cdots p_{k'}=p_{j-k'+1}\cdots p_j
\qquad(1<k'<k<j)
\tag{4-10}
$$

从而：

$$
next[j+1]=next[k]+1
\tag{4-11}
$$

若沿链退到 0 仍无可扩展候选，则：

$$
next[j+1]=1
\tag{4-12}
$$

```text
get_next(T, next):
    i <- 1; next[1] <- 0; j <- 0
    while i < T[0]:
        if j == 0 or T[i] == T[j]:
            i <- i + 1; j <- j + 1
            next[i] <- j
        else:
            j <- next[j]
```

循环开始时，`next[1..i]` 已确定，`j` 表示当前可扩展的最长候选位置。每次要么推进 `i`，要么沿已经求出的 `next` 链缩短候选；算法 4.7 的时间复杂度为 $O(m)$。

对模式 `'abaabcac'`，已知 `next[6]=3`，但 $p_6\ne p_3$，再退到 `next[3]=1` 仍不相等，所以 `next[7]=1`；随后 $p_7=p_1$，故 `next[8]=2`。

#### 算法 4.8：`nextval` 消除重复比较

若失配位置 `j` 与回退位置 `k=next[j]` 的字符仍相等，即 $p_j=p_k$，那么刚刚与 $p_j$ 不等的主串字符也必然与 $p_k$ 不等。`nextval` 继续沿回退链跳过这次必败比较：

```text
get_nextval(T, nextval):
    i <- 1; nextval[1] <- 0; j <- 0
    while i < T[0]:
        if j == 0 or T[i] == T[j]:
            i <- i + 1; j <- j + 1
            if T[i] != T[j]: nextval[i] <- j
            else:             nextval[i] <- nextval[j]
        else:
            j <- nextval[j]
```

原书 PDF 第 94 页的未编号对照表给出模式 `'aaaab'`：

| $j$ | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| $p_j$ | a | a | a | a | b |
| $next[j]$ | 0 | 1 | 2 | 3 | 4 |
| $nextval[j]$ | 0 | 0 | 0 | 0 | 4 |

使用 `nextval` 时，算法 4.6 的匹配框架不变，只把失配回退表换为修正后的表。

> **⚠ 易错提醒**
>
> `next` 的数值依赖教材的 1 起始定义，不能与“前缀长度从 0 开始”的其他写法直接混用。KMP 优化的是失配后的回退：`i` 不回退，`j` 可能多次回退；成功位置仍是 `i-m`。

### 4.4.1 文本编辑：文本串、页表与行表

文本可视为一个**文本串**；页是文本串的子串，行又是页的子串。编辑器通过索引表保存这些子串的存储映像：

| 结构 | 表项内容 | 作用 |
| --- | --- | --- |
| 页表 | 页号、该页起始行号 | 从页定位到行范围 |
| 行表 | 行号、起始地址、该行子串长度 | 从行定位到文本串中的字符区间 |
| 当前指针 | 页指针、行指针、字符指针 | 指示当前操作对象 |

教材图 4.8 的单页行表示例为：

| 行号 | 起始地址 | 长度 |
| ---: | ---: | ---: |
| 100 | 201 | 8 |
| 101 | 209 | 17 |
| 102 | 226 | 24 |
| 103 | 250 | 17 |
| 104 | 267 | 15 |
| 105 | 282 | 2 |

更新规则决定编辑是否正确：

1. 行内插入或删除字符后，更新该行长度；若新长度超出原分配空间，重新分配该行并修改起始地址。
2. 插入或删除整行时，对行表执行插入或删除。行表按行号递增存储，因此还要移动操作位置后的表项。
3. 若删除的是某页起始行，把页表中该页的起始行号改为下一行行号。
4. 页表的维护与行表同理。删除行或页时可只修改页表、行表，不立即删除所涉及字符，从而避免大段字符搬移。

### 4.4.2 书名关键词索引

关键词索引把“关键词 → 含该词的书号集合”组织为按词典有序的表。图 4.9 中的最小映射例如：

| 关键词 | 书号索引 |
| --- | --- |
| `analysis` | 034, 050, 067 |
| `data` | 005, 010, 023 |

#### 算法 4.9：生成索引表的总流程

对书目文件重复以下步骤直到文件结束：

1. 先初始化空索引表；教材还在 `idxlist.item[0]` 放置空串哨兵。随后读入一个包含书号与书名的书目串。
2. 顺序扫描书名串并分离单词；查常用词表，排除 `an`、`a`、`of`、`the` 等常用词，把其余词放入本书的临时词表。
3. 对临时词表中的每个关键词查询索引表：已有词项时追加书号；没有时按词典序插入新词项，再追加书号。
4. 全部书目处理完后输出索引表。

数据结构的选择服务于不同操作：

| 对象 | 表示 | 选择依据 |
| --- | --- | --- |
| 单本书的临时词表 `wdlist` | 字符串顺序表 | 关键词数量有限 |
| 关键词索引表 `idxlist` | 按词典序排列的顺序表 | 索引表主要用于查找，教材计划采用第 9 章的折半查找 |
| 索引项的关键词 `key` | 堆分配串 `HString` | 关键词常驻且长度不等，按实际长度存储 |
| 索引项的书号集合 `bnolist` | 书号链表 | 书号逐个加入，各关键词对应的书号数量可能差异很大 |

#### 算法 4.10—4.14：查询并插入索引项

```text
InsIdxList(idxlist, bno):                       // 算法 4.10
    for each keyword wd in wdlist:
        (j, found) <- Locate(idxlist, wd)
        if not found: InsertNewKey(idxlist, j, wd)
        if InsertBook(idxlist, j, bno) fails: return OVERFLOW
    return OK
```

| 算法 | 操作合同与关键更新 |
| --- | --- |
| 算法 4.11 `GetWord(i, wd)` | 取临时词表第 `i` 个字符串，通过 `StrAssign` 生成关键词串 `wd` |
| 算法 4.12 `Locate(idxlist, wd, b)` | 从有序索引表后部向前比较；相等时令 `b=TRUE` 并返回已有位置，否则令 `b=FALSE` 并返回保持词典序的插入位置 |
| 算法 4.13 `InsertNewKey(idxlist, i, wd)` | 从表尾向后移动 `[i, last-1]` 的词项，在 `i` 复制关键词、初始化空书号链表，再增加表长 |
| 算法 4.14 `InsertBook(idxlist, i, bno)` | 为书号分配链结点并追加到第 `i` 个关键词的书号链表；分配失败返回错误 |

不变量是：处理完每个关键词后，`idxlist` 仍按词典序排列；每个词项的 `bnolist` 只保存该关键词对应的书号。新关键词必须先创建词项并初始化空链表，之后才能插入书号。

## 章末对照

| 维度 | 朴素匹配（算法 4.5） | KMP（算法 4.6） |
| --- | --- | --- |
| 失配后的主串指针 | 回到下一候选起点 | 保持不变 |
| 失配后的模式指针 | 回到 1 | 回到 `next[j]` 或 `nextval[j]` |
| 预处理 | 无 | 由模式串求回退表，算法 4.7 为 $O(m)$ |
| 最坏时间 | $O(nm)$ | 匹配连同预处理为 $O(n+m)$ |
| 适用特点 | 结构简单；部分匹配少时实际比较次数可较低 | 部分匹配多时避免主串回溯，可顺序扫描外部输入 |
